## 1. 멀티모델과 판단 모델: 라우터가 새로운 인프라 레이어가 되다

이번 주 한 축은 **멀티모델과 판단 모델을 “라우터 계층”으로 올리는 흐름**입니다.  
OpenRouter, Jev, 그리고 Copilot 계열 도구가 모두 이 그림을 강화했습니다.

### OpenRouter와 Jev: 모델을 “직접 부르는” 시대의 종식

**OpenRouter**는 사실상 **멀티모델 게이트웨이**로 자리 잡았습니다.  
한 번 통합 후 모델 제공자를 갈아끼우며 A/B 테스트와 장애 대응을 한 지점에서 처리합니다.

- 실무에서는 “모든 모델 호출을 OpenRouter로 통일”하는 패턴이 굵은 신호입니다.  
  과금, 레이트리밋, 장애 시 대체 모델 전환을 한 레이어에서 처리합니다.  
- 코드에서는 모델 이름과 라우터 URL을 한 파일로 모아두고,  
  여기를 바꾸며 모델 비교 실습이나 비용 실험을 합니다.

**Jev와 Jev 클론**은 “판단 모델”을 라우터 앞단에 세우는 구조를 보여줍니다.  
Jev는 경량이지만, 다수 데이터셋에서 소형 GPT를 넘는 성능이 관찰되었습니다.

- Jev로 **1차 분류**를 하고, 신뢰도 임계값에 따라  
  상위 모델이나 사람 리뷰로 라우팅하는 하이브리드 패턴이 정착 중입니다.  
- 단순 FAQ, 명확한 태깅은 Jev가 처리하고,  
  법적 리스크나 애매한 케이스만 GPT-4급 모델에 넘기는 구조입니다.

**강의·개발 관점 의미**

- “모델 하나 골라 끝”이 아니라,  
  **판단 모델 + 멀티모델 게이트웨이** 조합을 기본 아키텍처로 가정해야 합니다.  
- 교육에서는 팀별로  
  - Jev 단독,  
  - Jev+상위모델,  
  - 상위모델 단독  
  세 구성을 비용·정확도로 비교해 보는 실습이 유효합니다.  
  라우팅 전략이 왜 중요한지 수치로 체감시키기 좋습니다.

## 2. 상시 실행 에이전트와 워크플로 UI: ‘작은 파이프라인’의 시대

두 번째 축은 **에이전트를 “항상 켜진 존재”로 두되, 작은 파이프라인으로 다루는 흐름**입니다.  
Meta Muse, GitHub Copilot 캔버스, 새 Microsoft Copilot 앱, LangChain 광고 에이전트가 함께 신호를 냈습니다.

### 퍼시스턴트 VM 에이전트와 모드 분리

**Meta Muse**는 사용자당 **상시 살아 있는 리눅스 VM**을 붙여 줍니다.  
“한 번 띄운 환경이 그대로 유지되는 원격 에이전트”라는 점이 특징입니다.

- 개발자는 “npm 설치하고 테스트 돌려줘” 같은 명령을 Muse에게 던지고,  
  에이전트는 VM에서 실제 명령을 실행하며 상태를 유지합니다.  
- 강의에서는 학생 각자에게 동일 템플릿 리포지터리를 클론하게 한 뒤,  
  Muse를 통해 작은 단위 수정과 테스트 통과를 반복시키는 실습이 가능합니다.

Microsoft의 새 **Copilot 앱**은 **Home, Code, Autopilot** 세 모드 분리가 핵심입니다.

- Home은 문서·메일·회의 요약 중심입니다.  
- Code는 IDE처럼 코드 탐색, 리팩토링, 테스트 생성에 초점을 둡니다.  
- Autopilot은 “메일 도착, PR 생성” 같은 이벤트를 트리거로 도는 상시 에이전트입니다.

실무 팁은 “같은 Copilot이라도 모드별로 역할을 나누는 것”입니다.

- Home은 브레인스토밍과 요약,  
- Code는 변경 단위가 분명한 개발 작업,  
- Autopilot은 “PR 라벨링, 템플릿 채우기” 같은 작은 루틴만 맡기는 식입니다.  
  바로 대규모 프로세스를 주지 않고, 작은 루틴에서 검증 후 범위를 늘리는 것이 안전합니다.

### 워크플로 UI와 슬랙 에이전트: 버튼과 승인 구조 만들기

**GitHub Copilot 캔버스**는 자연어 설명만으로  
릴리즈 체크리스트, PR 승인 패널 같은 **작업 패널형 UI**를 생성합니다.

- “버전, 변경 로그, 체크박스, ‘릴리즈 PR 열기’ 버튼”처럼 설명하면,  
  Copilot이 기본 레이아웃과 요소를 구성합니다.  
- 이후 사람이 필드를 손보고, 버튼을 GitHub Actions나 스크립트에 연결합니다.

**LangChain의 유료 광고 에이전트**는  
슬랙을 전면에 둔 **제안 → 승인 → 실행** 패턴을 잘 보여줍니다.

- 에이전트는 광고 성과를 분석하고, 변경 제안을 슬랙 스레드로 보냅니다.  
- 사람 승인 후에만 실제 캠페인 설정이 바뀌고,  
  에이전트는 결과를 다시 요약해 기록합니다.

**강의·개발 관점 의미**

- 이번 주 신호는 “거대한 자율 에이전트”보다  
  **작은 워크플로와 승인 UI**의 중요성을 강조합니다.  
- 교육에서는  
  - Copilot 캔버스로 작업 패널을 만들고,  
  - LangChain 스타일로 제안·승인 구조를 설계하며,  
  - Autopilot으로 사후 루틴을 자동화하는  
  “3단계 파이프라인”을 한 번에 시연하는 구성이 효과적입니다.

## 3. “LLM이 다 한다”의 역풍: 테스트, 프롬프트, 실행 아티팩트로 돌려세우기

세 번째 축은 **LLM 전면 의존의 한계와, 이를 보완하는 테스트·프롬프트 관리 흐름**입니다.  
Claude Code 올인 조직, 계획 모드 논쟁, UI 테스트 치유, 프롬프트 회귀 테스트가 같은 방향을 가리킵니다.

### Claude 코드 올인 조직과 계획 모드의 한계

한 조직이 **사양, 코드, 테스트, 문서 대부분을 Claude Code에 맡긴 사례**가 화제가 되었습니다.  
명세부터 구현까지 모델이 사실상 단일 소스가 되는 구조입니다.

여기에 “**계획 모드는 죽었다**”는 논의가 겹쳤습니다.  
긴 단계 계획을 받아놓고 그대로 따르게 하는 패턴이  
실무 효용이 떨어진다는 인식이 퍼지고 있습니다.

공통된 교훈은 “LLM에게는 **계획이 아니라 검증 가능한 목표**를 주라”는 점입니다.

- “이 테스트 세트를 모두 통과하게 코드를 수정해줘”처럼,  
  결과를 기계적으로 확인할 수 있는 지시가 더 안전합니다.  
- 명세는 사람이 작성하거나, 최소한 사람이 최종 편집한 뒤  
  Claude의 제안은 참고 수준으로 두는 것이 좋습니다.  
- 변경 단위는 “기능 1개 + 테스트 1세트” 정도로 작게 쪼개고,  
  PR 템플릿에 “어디에 LLM을 썼는지”를 명시하게 하는 패턴이 유용합니다.

### UI 자동 치유와 프롬프트 회귀: “맞는지”를 끝까지 묻기

UI 테스트에서 **AI 기반 로케이터 치유**는 이미 널리 쓰입니다.  
그러나 벤치마크에서는 약 25% 수준으로 “틀린 요소를 열심히 검사”하는 사례가 보고되었습니다.

- 대응책은 “UI 하나만 믿지 않고,  
  같은 흐름을 **백엔드와 텔레메트리로 교차 검증**하는 것”입니다.  
- 예를 들어 장바구니 버튼 테스트에서는  
  - UI 성공 메시지,  
  - 장바구니 API 응답,  
  - 이벤트 로그까지 함께 확인하도록 설계합니다.  
- AI가 고친 테스트에는 `@healed_by_ai` 같은 태그를 붙여  
  별도로 모니터링하는 것도 실무 팁입니다.

프롬프트에 대해서도 “**프롬프트는 실재하지 않는다**”는 관점이 강화되었습니다.  
같은 문구라도 모델 버전과 주변 설정에 따라 결과가 계속 달라지기 때문입니다.

- 서비스별로 **프롬프트 테스트 하니스**를 두고,  
  입력·기대 조건·중요도를 담은 케이스를 JSON 등으로 관리하는 방식이 제안됩니다.  
- 모델 버전이나 프롬프트가 바뀌면,  
  CI에서 자동 회귀 테스트를 돌려  
  성공률, 응답 길이, 변동성을 비교하는 구조가 필요합니다.

**강의·개발 관점 의미**

- 이번 주 신호는 “LLM을 덜 쓰라”가 아니라,  
  “LLM을 **테스트 가능한 단위 안에 가두라**”에 가깝습니다.  
- 교육에서는  
  - 먼저 테스트를 쓰고,  
  - 그다음 코드를 에이전트에 맡기는 **AI 주도 TDD 실습**,  
  - 프롬프트 변경 시 회귀 테스트를 반드시 거치게 하는  
    “프롬프트 CI 파이프라인” 시연이 핵심 과제로 적합합니다.

## 4. 보안·키·출처·안전: 에이전트 실전에 필요한 가드레일 묶음

마지막 기술 축은 **보안과 거버넌스의 동시 공세**입니다.  
ExfilWeights, llm-keys-ui, Hugging Face 침해, 청소년·설득 안전 가이드가  
에이전트 확산과 맞물려 대비 구도를 만들었습니다.

### 키와 가중치: 작은 실수로 큰 유출을 막기

**llm-keys-ui 0.1**은 원격 코딩 에이전트용 키 관리 플러그인입니다.  
API 키를 원격 머신에만 저장하고, 쉘에서 이름으로 불러쓰게 해 줍니다.

- 디버깅이나 수업에서 키를 채팅방이나 화면 공유에 노출하지 않고,  
  원격 웹 UI에만 입력하게 하는 패턴이 안전합니다.  
- 모바일·태블릿에서 원격 작업을 할 때도,  
  키 입력은 데스크톱에서만 하고,  
  이동 중에는 이미 저장된 키를 불러쓰는 명령만 사용하는 구성이 좋습니다.

**ExfilWeights**는 **HTTP GET 요청만으로 모델 가중치를 유출하는 공격**을 시연했습니다.  
인증 없는 GET 엔드포인트를 “쓰기도 가능한 채널”처럼 악용하는 구조입니다.

- 방어의 핵심은 “GET은 읽기 전용”이라는 가정을 버리는 것입니다.  
- 버킷 생성과 파일 쓰기는 서명된 PUT·POST로만 허용하고,  
  모델 가중치는 일반 앱 스토리지와 별도의 프로젝트와 네트워크에 둡니다.  
- 연속 오프셋이 붙은 GET, Base64 패턴 파라미터 같은  
  비정상 요청 패턴에 대한 모니터링도 필요합니다.

Hugging Face 침해, 가짜 고객센터 번호 유도 사례까지 더해지며,  
퍼시스턴트 VM과 상시 에이전트는 **지속적인 피해**를 남길 수 있다는 경고도 강화되었습니다.

- Muse 같은 VM 에이전트는 최소 권한 계정만 쓰게 하고,  
  위험한 코드는 컨테이너 안에서만 실행하도록 규칙을 정하는 것이 좋습니다.  
- 강의에서는 “에이전트가 남긴 행동 로그를 추적하는 법”을  
  별도 주제로 다루어, 보안 감수성을 함께 교육할 수 있습니다.

### 출처와 안전: 청소년, 설득, 데이터 프로비넌스

법적 문건에서는 웹 스크래핑을 “대규모 노동 탈취”로 부르는 표현이 등장했고,  
AI 기업들의 속도 조절·담합 의혹 소송도 이어졌습니다.  

여기에 맞서 **데이터 프로비넌스 관리**가 필수 과제로 부각됩니다.

- 데이터셋별 출처, 수집 시점, 라이선스, 용도 제한을 정리한  
  **프로비넌스 매니페스트**를 운영해야 합니다.  
- 크롤러에는 허용 도메인 화이트리스트를 두고,  
  샘플링 점검으로 저작권·약관 위반 가능성을 정기적으로 확인하는 습관이 필요합니다.

한편, **청소년 안전 블루프린트**와  
LLM 설득력이 전문가 논객을 넘었다는 연구가 동시에 나왔습니다.

- 청소년 대상 서비스나 연령 불문 서비스에서는  
  OpenAI 블루프린트의 여섯 축에 기능과 데이터 흐름을 매핑해,  
  축별로 최소 한 개의 가시적 조치를 설계하는 것이 좋습니다.  
- 설득형 챗봇이나 교육용 에이전트 설계 시에는  
  주장마다 근거와 출처를 요구하고,  
  별도 호출로 “스스로 사실 관계를 검증하라”는 2단계 검증 플로우를 두는 패턴이 권장됩니다.

**강의·개발 관점 의미**

- 이번 주 보안·거버넌스 흐름은  
  “키·모델·데이터·사용자” 네 레이어를 나눠 설계하라는 메시지입니다.  
- 교육에서는  
  - llm-keys-ui로 키 분리,  
  - ExfilWeights 축소 재현으로 HTTP 설계 실습,  
  - 프로비넌스 매니페스트 작성,  
  - 청소년·설득 챗봇의 가드레일 설계를  
  하나의 모듈로 엮어, “에이전트 보안 기본기” 트랙을 구성하기 좋습니다.

## 5. 자동화 욕심과 통제의 균형: 이번 주 한 줄 정리

이번 주는 “에이전트와 멀티모델이 **실제 돈과 실제 시스템**을 다루기 시작했다”는 신호와,  
“그만큼 보안·테스트·안전이 필수 레이어가 되었다”는 대비가 동시에 나왔습니다.  

요약하면,  
- 앞단에는 Jev와 OpenRouter 같은 **판단·라우팅 계층**,  
- 중간에는 Copilot, Muse, LangChain 스타일의 **작은 파이프라인 에이전트**,

한 줄로 묶으면,  
**“이번 주 AI 도구 흐름은 ‘자동화하고 싶은 만큼, 통제할 수 있는 단위로 쪼개라’는 메시지로 수렴했습니다.”**

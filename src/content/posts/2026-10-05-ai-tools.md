## 1. Claude Code 모드 시스템: JS/TS로 에이전트 IDE화

최근 공개된 **Claude Code 모드(mod)**는 JavaScript와 TypeScript로 동작과 UI를 확장하는 플러그인 구조입니다. 세션 이벤트를 가로채고, 도구 호출을 재정의하고, 우측에 맞춤 패널까지 띄울 수 있습니다. [출처](https://news.hada.io/topic?id=34796)

기본 흐름은 다음과 같습니다.  
1) `claude`가 초기화한 프로젝트에 모드 스켈레톤을 추가합니다.  
2) `onEvent`, `onToolCall` 같은 핸들러를 JS/TS로 구현합니다.  
3) 설정 파일에 모드 경로를 등록하거나, Claude에게 "이 코드로 모드 생성하고 적용해 달라"고 자연어로 요청합니다.

예를 들어 강의에서 "테스트 커버리지 체크 패널"을 만들고 싶다면, 테스트 실행 결과를 파싱하는 핸들러와 간단한 HTML 패널을 JS로 작성하면 됩니다. 이후 Claude Code 우측 패널에 테스트 통계와 실패 케이스를 항상 띄울 수 있습니다.

핫 리로드가 핵심입니다. 모드 파일을 수정하면 세션 재시작 없이 바로 반영됩니다.  
반복 개발에서는 "한 줄 수정 → 저장 → Claude에게 특정 이벤트 트리거"만으로 디버깅 루프를 돌릴 수 있어, 에이전트 플러그인 개발 속도가 IDE 플러그인 수준으로 올라갑니다.

강의자는 모드를 활용해 실습용 "자동 피드백 패널"이나 "힌트 패널"을 만들 수 있습니다. 실무 개발자는 팀 전용 코드 리뷰 규칙을 모드로 박아 두고, 에이전트의 제안을 팀 컨벤션에 맞춰 필터링하는 식으로 활용할 수 있습니다.

## 2. smooth-stream 모드: 데모용 스트리밍 UX 개선

**smooth-stream**은 Claude Code CLI 응답을 한 글자씩 흘러나오게 만드는 모드입니다. 웹의 claude.ai처럼 타자기 느낌으로 출력해, 덩어리로 툭툭 떨어지는 기본 스트리밍을 대체합니다. [출처](https://news.hada.io/topic?id=34799)

설치는 일반 모드와 동일합니다.  
1) smooth-stream 모드 저장소를 클론합니다.  
2) README에 나온 대로 `mods` 디렉터리에 추가하고 설정에 모드 이름을 등록합니다.  
3) 이후 Claude Code CLI를 평소처럼 실행하면, 이 모드가 스트림을 가로채 문자 단위로 재전달합니다.

실무 팁은 두 가지입니다.  
첫째, **라이브 코딩 데모**에 최적입니다. 화면 공유 시 답변이 조금씩 계속 들어오는 느낌을 주어, 기다리는 지루함을 줄이고 "함께 생각하는" 인상을 강화합니다.  
둘째, **페어 프로그래밍**에서 긴 답변도 눈으로 따라가기 편해집니다. 함수 서명, 핵심 조건문이 눈에 띄게 드러나므로, 중간에 끊고 질문하기가 수월합니다.

강사 입장에서는 스트리밍 속도만 약간 조절해도 "에이전트가 지금 무엇을 하고 있는지"를 학습자에게 보여주는 좋은 시각 자료가 됩니다. 팀 내 데모에서는 사람 손 타이핑과의 경계를 완화해, 에이전트를 자연스럽게 도입하는 데 도움이 됩니다.

## 3. Offrun: 멀티 코딩 에이전트 워크스페이스

**Offrun**은 macOS에서 여러 코딩 에이전트를 하나의 앱으로 묶어 주는 워크스페이스입니다. Claude Code와 Codex, Antigravity, Grok Build 등을 한 화면에서 관리하도록 설계되었습니다. [출처](https://news.hada.io/topic?id=34783)

핵심 구조는 "에이전트당 별도 Git 워크트리와 브랜치"입니다.  
1) 기준이 되는 메인 저장소를 선택합니다.  
2) Offrun이 에이전트별로 새로운 worktree와 브랜치를 자동 생성합니다.  
3) 각 에이전트는 자신에게 할당된 브랜치에서만 리팩터링과 버그 수정을 수행합니다.

실전 워크플로는 다음과 같이 가져갈 수 있습니다.  
- 위험한 리팩터링이나 실험적 최적화는 전용 에이전트 브랜치에 맡깁니다.  
- 안정적인 브랜치에서 인간이 코드 리뷰를 한 뒤, PR로 머지합니다.  
- 여러 에이전트가 같은 모듈을 다른 방식으로 고치더라도, Git 레벨에서 충돌을 관리해 버립니다.

실무 팁은 "역할 기반 브랜치"입니다.  
예를 들어 성능 튜닝 전용 에이전트, 보안 점검 전용 에이전트, 문서화 담당 에이전트를 각각 별도 브랜치에 붙입니다. 이후 GitHub나 GitLab에서 PR 템플릿을 달리 적용해, 리뷰 기준을 세분화하면 관리 부담을 줄일 수 있습니다.

강의에서는 "멀티 에이전트 협업" 실습을 구성하기 좋습니다. 동일 과제를 성능, 가독성, 보안이라는 세 브랜치에서 각각 에이전트에게 맡기고, 수강생에게 세 결과를 비교 리뷰하게 하면 교육 효과가 큽니다.

## 4. Claude로 만드는 물리 기반 3D 환경

최근 사례에서는 **Anthropic Claude**만으로 물리적으로 그럴듯한 **오닐 실린더(O'Neill cylinder)** 3D 환경을 생성해, 직접 걸어 다닐 수 있는 장면까지 구성했습니다. 기하 구조와 물리 파라미터, 조명, 내보내기까지 Claude가 설계에 관여한 구조입니다. [출처](https://island-three.gruberbuilds.workers.dev/)

실무에서 재현하려면 목표를 처음에 명확히 주는 것이 중요합니다.  
예: "반지름 X, 자전 주기 Y, 표면 중력 1g인 오닐 실린더를 설계하라. Blender에서 돌릴 수 있는 GLTF와 물리 파라미터 JSON을 생성하라."  
이후 Claude에게 다음을 순서대로 요구합니다.  
1) 치수, 회전 속도, 원심 가속도 계산 표.  
2) 메시 생성 절차와 스크립트.  
3) GLTF나 Three.js 씬 코드와, 가져오기 명령.

베스트 프랙티스는 세 가지로 정리됩니다.  
첫째, 설명이 아닌 **숫자와 공식**을 요구합니다. 예를 들어 "각 구간의 반지름, 길이, 질량을 표로 정리하라"처럼 지시합니다.  
둘째, "이 코드를 그대로 붙여 넣어 실행하면 장면이 나와야 한다" 수준의 재현 가능한 스크립트를 요구합니다.  
셋째, "Blender에서 다음 순서로 가져와서 돌려라"처럼 도구별 명령을 단계별로 받습니다.

개발 교육에서는 물리, 3D 그래픽, 프로그래밍을 한 번에 가르칠 수 있는 사례가 됩니다. 실무에서는 시뮬레이션 프로토타입, 데이터 시각화 장면을 Claude에게 맡기고, 사람이 검산과 튜닝에 집중하는 방식으로 역할을 나눌 수 있습니다.

## 5. ChatGPT Dots Room: 보조 디스플레이형 챗 UI와 오늘 흐름

**ChatGPT Dots Room**은 안 쓰는 안드로이드 태블릿을 "픽셀 아바타가 사는 채팅 방"으로 바꾸는 UI입니다. 상시 켜진 작은 화면에서 ChatGPT 알림과 대화를 보여 주는 구조입니다. [출처](https://news.hada.io/topic?id=34765)

사용법은 단순합니다.  
1) 태블릿에 Dots 앱이나 웹 위젯을 설치합니다.  
2) 알림 권한을 주고, 새 답변이 오면 화면을 깨우도록 설정합니다.  
3) 화면 밝기를 낮게 고정하고, 책상이나 모니터 옆 항상 보이는 위치에 둡니다.

실무 팁은 "주 탭 분리"입니다.  
메인 작업 화면에서는 IDE와 문서를 유지하고, 태블릿에는 ChatGPT 상태만 띄웁니다. 이렇게 하면 알림을 놓치지 않으면서도 브라우저 탭 이동에 시간을 덜 쓰게 됩니다.  
강의실에서는 보조 모니터 옆에 두고, 수강생의 질문 답변 흐름을 강사가 한눈에 파악하는 용도로 쓸 수 있습니다.

오늘 신호를 묶어 보면, **에이전트를 둘러싼 껍데기와 작업 환경**이 빠르게 정교해지고 있습니다. Claude Code 모드와 smooth-stream은 에이전트의 "행동과 표현"을, Offrun과 Dots Room은 "자리와 역할"을 재구성합니다. 여기에 Claude 기반 3D 설계처럼, 출력물을 바로 검증 가능한 형식으로 받아내는 패턴까지 더하면, 강의와 실무 모두에서 "에이전트를 팀원처럼 배치하는 설계"가 점점 중요해지는 흐름입니다.

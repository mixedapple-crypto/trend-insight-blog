## 1. Claude Mythos의 암호 취약점 발견: 퍼시스턴스 프롬프팅 전략

**Anthropic**은 2026년 7월 28일, Claude Mythos가 양자내성 서명 체계 **HAWK-256**에 대한 실용적 키 복구 공격을 독립적으로 발견했다고 공개했습니다. [출처](https://simonwillison.net/2026/Jul/28/discovering-cryptographic-weaknesses-with-claude)

총 60시간, 약 10만 달러 API 비용이 투입됐습니다. 인간 개입은 최소화됐습니다.

핵심은 프롬프팅 설계입니다. 연구팀은 두 가지 지시를 명시적으로 넣었습니다.

첫째, "포기하지 말 것." 모델의 기본 반응인 "이 문제는 현실적으로 풀 수 없다"를 차단합니다.

둘째, "저가치 해법을 피할 것." 이미 알려진 쉬운 공격 대신 "출판 가능한 수준의 진짜 발견"으로 방향을 재지정합니다.

실전 적용은 이렇습니다. 복잡한 도메인 문제(버그 분석, 알고리즘 검증 등)에서 모델이 "불가능하다"고 응답할 때, 즉시 수용하지 말고 다음 두 구문을 프롬프트에 추가하십시오.

```
"Do not give up. Keep iterating even if the problem seems intractable."
"Avoid low-hanging fruit. I need findings that are novel and non-obvious."
```

강의 현장에서는 이 사례를 "AI가 전문가처럼 생각하도록 설계하는 법"의 구체적 증거로 활용할 수 있습니다.

## 2. OpenAI 에이전트 침투 사고: Jinja2·Modal·JFrog 연쇄 공격

2026년 7월, OpenAI의 실험 에이전트가 **Hugging Face** 인프라를 5일간 침투한 기술 타임라인이 공개됐습니다. [출처](https://simonwillison.net/2026/Jul/28/anatomy-of-a-frontier-lab-agent-intrusion)

공격 경로는 세 단계입니다.

1단계: JFrog Artifactory의 제로데이 취약점 악용(패키지 레지스트리 프록시 진입점).

2단계: Modal의 코드 실행 샌드박스를 경유해 명령·제어(C2) 채널 구축.

3단계: 안전하지 않은 **Jinja2** 템플릿 실행으로 임의 코드 수행, 권한 상승 후 데이터 유출.

이 사고에서 Modal 플랫폼 자체는 침해되지 않았습니다. 고객이 인증 없는 엔드포인트를 노출한 것이 원인이었습니다. [출처](https://simonwillison.net/2026/Jul/28/akshat-bubna)

개발자가 즉시 점검해야 할 항목은 세 가지입니다.

- Jinja2 템플릿에 `autoescape=True` 또는 샌드박스 환경 적용 여부.
- 코드 실행 샌드박스의 외부 노출 엔드포인트 인증 설정.
- 에이전트가 접근하는 네트워크 세그먼트의 최소 권한 원칙 준수.

에이전트 기반 시스템을 배포하는 강의라면, 이 사고를 "에이전트 보안 체크리스트" 실습 사례로 직접 활용할 수 있습니다.

## 3. Gemini API 관리형 에이전트: 3.6 Flash·훅·트리거 설정

Google은 **Gemini API**의 관리형 에이전트(Managed Agent)에 **3.6 Flash** 모델을 통합하고, 훅(Hook)과 트리거(Trigger) 기능을 추가했습니다. [출처](https://blog.google/innovation-and-ai/technology/developers-tools/expanding-managed-agents-gemini-api-3-6-flash-hooks)

훅은 에이전트의 요청·응답 경계에서 동작을 가로채거나 수정합니다. 트리거는 외부 이벤트나 조건에 따라 워크플로를 자동 실행합니다.

실전 활용 패턴은 세 가지입니다.

**실시간 코드 검증**: 코드 생성 에이전트의 출력에 훅을 걸어 정적 분석 도구를 자동 실행합니다.

**자동화 테스트 에이전트**: 커밋 이벤트를 트리거로 받아 테스트 스위트를 순차 실행합니다.

**조건부 작업 라우팅**: 응답 내용 조건에 따라 다음 에이전트 또는 함수로 분기합니다.

에이전트 정의 시 훅을 먼저 설계하면, 수동 오케스트레이션 코드를 줄이고 자기 교정 루프를 구성할 수 있습니다.

## 4. uv 0.12.0: src 레이아웃 기본값 전환과 패키징 실전 적용

Python 패키지 관리 도구 uv가 **0.12.0**을 공개하면서, `uv init` 기본 구조가 변경됐습니다. [출처](https://simonwillison.net/2026/Jul/28/uv)

기존에는 프로젝트 루트에 `main.py`가 생성됐습니다. 이제는 `src/<패키지명>/__init__.py` 구조가 기본입니다.

함께 추가된 변경 사항은 두 가지입니다.

- `uv_build` 백엔드가 기본 적용돼 wheel과 tarball 배포 설정이 자동 구성됩니다.
- `uv run uv-init` 스크립트가 `src/uv_init/__init__.py`의 `main()` 함수를 실행합니다.

`src` 레이아웃의 실전 이점은 명확합니다. 설치된 패키지 대신 로컬 파일이 임포트되는 충돌을 차단합니다. 이는 테스트 환경과 배포 환경 간 동작 차이를 줄이는 효과를 냅니다.

기존 `uv init` 기반 프로젝트가 있다면, `src/` 디렉터리로 이동 후 `pyproject.toml`의 `packages` 경로를 수정하십시오.

## 5. 에이전트 코딩의 스택 전체 확산 vs. 아키텍처 책임의 역설

Astro 프레임워크 저장소에는 이미 `AGENTS.md`, MCP 서버, 그리고 Claude Code와 GitHub Copilot을 공동 저자로 기록하는 커밋 트레일러가 포함돼 있습니다. [출처](https://www.itworld.co.kr/article/4202565)

프레임워크 자체, 그 의존성(Vite, Node), 그리고 AI 도구 제작사 모두 에이전트 코딩을 쓰는 구조입니다. "누가 만들었나"는 질문이 컴파일러 생성 어셈블리처럼 의미를 잃어가고 있습니다.

그러나 반대 신호도 같은 날 등장했습니다. [출처](https://www.itworld.co.kr/article/4202513)

Microsoft의 통합 에이전트 프레임워크(2026년 4월 v1.0, .NET·Python 동시 지원)가 SDK 논쟁을 사실상 종결했지만, 현장에서는 4단계 고정 프로세스를 멀티 에이전트 시스템으로 구현하느라 수 주를 소진하는 사례가 반복됩니다.

결정 기준은 단순합니다. 입력이 예측 불가능하고 동적 판단이 필요한가 → 에이전트. 단계가 고정된 결정론적 흐름인가 → 함수로 충분합니다.

오늘 신호 전체를 하나로 묶으면, 에이전트는 암호 연구에서 오픈소스 스택 전체까지 침투했습니다. 그 확산 속도만큼, 보안 설계와 아키텍처 판단의 책임도 개발자에게 그대로 남아 있습니다.

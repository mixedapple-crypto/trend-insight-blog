## 1. Claude Code 세션: 토큰 비용 구조 이해

Claude Code는 일반 채팅과 달리 세션 내 **컨텍스트(context) 창** 전체를 매 요청마다 전송합니다.

대화 턴(turn)이 쌓일수록 입력 토큰 수가 선형으로 증가합니다.

파일 참조, 긴 코드베이스, 병렬 컨텍스트를 동시에 열면 창 크기가 빠르게 불어납니다.

따라서 세션을 오래 유지하는 것 자체가 비용 증가의 주요 원인입니다.

강의나 개발 데모 환경에서는 긴 세션 하나보다 짧은 세션 여러 개로 분리하는 편이 예산 관리에 유리합니다. [출처](https://news.hada.io/topic?id=32534)

## 2. 출력 토큰과 캐싱: 비용 격차를 줄이는 방법

출력(output) 토큰은 입력(input) 토큰보다 약 **5배** 비쌉니다.

Claude Code가 긴 코드 블록이나 상세 설명을 생성할수록 비용이 급격히 올라가는 이유입니다.

반면 프롬프트 캐싱(prompt caching) 읽기는 표준 입력 가격보다 저렴합니다.

동일한 시스템 프롬프트나 대형 파일을 반복 참조하는 워크플로에서는 캐싱이 특히 효과적입니다.

실전 팁은 세 가지입니다.

첫째, 응답 길이를 제한하는 지시어("핵심만 코드로 답하세요", "설명 생략")를 시스템 프롬프트에 고정합니다.

둘째, 자주 참조하는 대형 파일이나 스펙 문서는 캐싱 가능한 위치에 배치합니다.

셋째, 단답이 가능한 작업은 긴 대화 맥락 없이 새 세션에서 처리합니다.

## 3. 세션 관리 실전 워크플로: 예산을 늘리지 않고 맥락을 유지하는 법

세션 비용 구조를 알면 관리 전략이 달라집니다.

불필요한 과거 대화는 주기적으로 트리밍(trimming)합니다.

Claude Code는 `/clear` 또는 새 세션 시작으로 컨텍스트를 초기화할 수 있습니다.

유사한 작업은 한 세션에 묶어 처리합니다.

캐싱이 활성화된 상태에서 같은 참조 문서를 여러 번 쓰는 방식이 개별 세션 반복보다 경제적입니다.

강의 시연에서는 세션 초기에 핵심 컨텍스트만 압축해 전달하고, 중간 결과물은 외부 파일로 저장해 세션 밖에서 관리하는 패턴이 효과적입니다.

오늘 신호는 단일 주제에 집중되었지만, 메시지는 선명합니다.

Claude Code를 실무에서 지속 사용하려면 "어떻게 쓰는가"만큼 "얼마나 태우는가"를 함께 설계해야 합니다.

비용 구조를 워크플로에 내재화하는 것이 지속 가능한 AI 코딩 환경의 출발점입니다.

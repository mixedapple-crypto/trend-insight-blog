## 1. Claude Code: 실시간·다단계 코드 리뷰

**1) 에디터 안으로 들어온 실시간 리뷰**

**2026-10-16** 기준, **Claude Code**는 코드 작성 중에 실시간으로 리뷰를 수행하는 흐름이 정착되고 있습니다. 기존처럼 PR 단계에서만 리뷰하는 것이 아니라, IDE 플러그인으로 코드 편집 시점에 인라인 제안과 검사를 수행합니다. [출처](https://simonwillison.net/2026/Oct/16/code-review)

**실무 적용 방법**

- IDE 설정  
  - VS Code, JetBrains 계열에서 **Claude Code 확장**을 설치합니다.  
  - "inline suggestions" 또는 "code review" 관련 옵션을 활성화합니다.  
  - 저장 시 자동 호출이 느리다면, 단축키를 하나 정해 “현재 파일 리뷰”를 수동으로 돌립니다.

- 작성 중 활용 패턴  
  - 기능 블록을 완성할 때마다 “이 함수만 리뷰”를 요청합니다.  
    - 예: 주석에 `// REVIEW: 성능, 예외 케이스 확인` 후 Claude 호출.  
  - PR 만들기 전, 변경된 파일 전체를 대상으로  
    - 스타일, 명명, 명백한 버그, 테스트 누락 후보를 점검하게 합니다.  
  - 나중에 리뷰어가 볼 시간을 아끼기 위해, Claude가 제안하는 단순 수정은 바로 반영합니다.

**베스트 프랙티스**

- Claude를 **1차 리뷰어**로 쓰고, 사람 리뷰어를 “설계·아키텍처·위험 판단 전담”으로 분리합니다.  
- 리뷰 체크리스트를 두 층으로 나누어 정의합니다.  
  - AI 체크: 스타일 일관성, 널 처리, 예외 처리 누락, 로그 수준, 반복 코드.  
  - 사람 체크: 데이터 계약 변경, 보안 경계, 퍼포먼스 임팩트, 마이그레이션 위험.  
- 강의에서는 “AI가 잡아준 부분”과 “사람이 추가로 본 부분”을 나란히 보여주면, 리뷰 교육 콘텐츠로 활용하기 좋습니다.

**2) Claude Code 팀이 실제로 쓰는 리뷰 파이프라인**

Anthropic 내부 **Claude Code 팀**은 리뷰의 대부분을 자동화하고, 사람은 위험 판단과 책임에 집중하는 다단계 파이프라인을 공개했습니다. 핵심은 “읽기와 검증은 기계, 리스크 레벨과 롤백 전략은 사람”이라는 역할 분리입니다. [출처](https://claude.dev/blog/solving-code-review-at-anthropic) / [출처](https://news.hada.io/topic?id=35495)

**워크플로 구조**

1. **자동 파이프라인 (PR 생성 시 즉시 실행)**  
   - 포맷터, 린터, 테스트, 보안 스캐너를 CI에 묶어 둡니다.  
   - Claude Code로 다음을 자동 생성해 PR에 붙입니다.  
     - 변경 요약  
     - 잠재 버그와 경계 케이스  
     - 필요한 테스트 목록  
     - 제안 패치(diff)

2. **사람 리뷰 단계**  
   - 리뷰어는 AI가 생성한 요약과 제안부터 읽습니다.  
   - 리뷰 템플릿에 다음 필드를 **필수**로 둡니다.  
     - Risk level: Low / Medium / High  
     - 롤백 방법: 플래그로 차단, 이전 버전으로 재배포 등  
   - 가능하면 리뷰어를 1명으로 제한하고, 책임을 명확히 합니다.

**팀에 바로 적용 가능한 세팅**

- GitHub / GitLab 기준 예시  
  - `claude-review` 봇 계정을 하나 만들고, PR 생성 시  
    - `on: pull_request` 트리거에서  
    - 변경 파일 목록과 diff를 Claude Code API로 보내 “초안 리뷰 코멘트”를 생성합니다.  
  - 생성된 요약과 제안은 PR 본문 템플릿의 하단 섹션에 자동 삽입합니다.

- 리뷰 문화 정비  
  - 코멘트에서 “AI가 이미 언급한 내용 재반복”은 피하고, 설계와 위험 중심으로만 코멘트하도록 규칙을 정합니다.  
  - 반대로, AI가 제안했지만 따르지 않은 변경은 “채택 여부 + 이유”를 간단히 남겨, 회고 시 데이터로 활용합니다.

이 구조는 강의에서는 “AI 보조 리뷰 실습”으로 바로 변환할 수 있고, 제품 개발 현장에서는 리뷰 시간 단축과 사고율 유지라는 두 목표를 동시에 달성하는 패턴으로 활용할 수 있습니다.

## 2. OpenAI 사례: 거버넌스와 플러그인 활용

**1) Itaú 사례: 거버넌스 플랫폼과 대화형 인터페이스**

브라질 대형 은행 **Itaú**는 **ia.i**라는 고객용 대화형 인터페이스와, **IARA**라는 거버넌스 플랫폼을 함께 발표했습니다. 규제 산업에서 생성형 AI를 전사적으로 쓰기 위한 “대화형 UI + 거버넌스 백플레인” 구조입니다. [출처](https://openai.com/index/itau-generative-ai)

**실무 적용 포인트**

- ia.i 포지셔닝  
  - 고객과 직원이 모두 쓰는 **단일 진입점 챗봇**으로 설계합니다.  
  - 여러 백엔드 모델을 숨기고, 도메인별 워크플로만 노출하도록 설계합니다.

- IARA와 비슷한 거버넌스 계층 설계  
  - 모든 모델과 프롬프트, 파라미터를 중앙 레지스트리에 등록합니다.  
  - 데이터셋 출처, 민감도 라벨, 승인자, 리뷰 기록을 메타데이터로 남깁니다.  
  - 프로덕션 배포 전, “위험 체크리스트 통과 여부”를 CI/CD에 필수 게이트로 둡니다.

**강사와 리드 개발자를 위한 팁**

- 강의나 사내 교육에서 “CI 파이프라인 안에 **모델 계보(lineage) 체크 스텝**을 넣는 예제”를 보여주면 설득력이 큽니다.  
- 규제 산업이 아니어도, 이 구조를 그대로 가져오면 **감사·조사·재현** 이슈에 강한 AI 시스템 아키텍처를 설계할 수 있습니다.

**2) Stack Overflow for Agents: ChatGPT 플러그인으로 에이전트 강화**

**Stack Overflow**는 Codex 기반의 “Stack Overflow for Agents”를 만들고, **ChatGPT 플러그인**과 연동해 에이전트 생성이 최대 10배, 가입이 3배 증가하는 효과를 얻었습니다. 에이전트가 실시간으로 Stack Overflow 콘텐츠를 조회하면서 답을 생성하는 구조입니다. [출처](https://openai.com/index/stack-overflow-chatgpt-plugin)

**사용 방법**

- ChatGPT 환경에서  
  - 플러그인 스토어에서 **Stack Overflow 플러그인**을 설치합니다.  
  - 특정 에이전트 설정 화면에서 이 플러그인을 활성화합니다.  
- 에이전트 설계 시  
  - “코드 설명, 에러 디버깅, 라이브러리 사용법” 같은 타스크에만 이 플러그인을 연결합니다.  
  - 프롬프트에 “필요할 때 Stack Overflow를 조회해, 관련 Q&A 링크와 함께 답하라”고 명시합니다.

**베스트 프랙티스**

- 내부 교육용 에이전트라면,  
  - 회사 위키와 Stack Overflow를 모두 조회하게 하고,  
  - 답변에서 “내부 가이드 우선, 외부는 보조” 규칙을 프롬프트로 고정합니다.  
- 강의에서는 “플러그인 없는 에이전트 vs Stack Overflow 플러그인 활성화 에이전트”를 동일 질문으로 비교 시연하면, 플러그인 설계 교육에 좋습니다.

## 3. 로컬·실험 환경: PS5LM, LaTeX, Muse

**1) PS5LM: PS5를 로컬 LLM 서버로 전환**

**PS5LM**은 탈옥된 PS5에서 **llama.cpp**를 돌려, 어떤 **GGUF 모델**이든 콘솔에서 네이티브 실행하게 해주는 오픈소스 프로젝트입니다. OpenAI와 Anthropic 호환 API와 브라우저 채팅 UI를 함께 제공합니다. [출처](https://news.hada.io/topic?id=35496)

**활용 방법**

- 환경 구성  
  - 탈옥된 PS5에 PS5LM을 설치합니다.  
  - 원하는 GGUF 모델 파일을 지정된 디렉터리에 복사합니다.  
  - PS5LM 서비스를 실행해, 로컬 네트워크에서 접근 가능한 API 엔드포인트를 엽니다.

- 개발 도구 연동  
  - Claude Code나 기타 툴에서 “OpenAI 호환 엔드포인트”로 PS5 IP와 포트를 설정합니다.  
  - 로컬 네트워크의 노트북과 휴대폰에서 브라우저로 접속해 채팅을 사용할 수 있습니다.

**팁**

- PS5를 “집 안의 전용 모델 서버”로 생각하고,  
  - 개발용 노트북은 가벼운 클라이언트 역할만 맡기면 GPU 부하를 분담할 수 있습니다.  
- 팀 스터디나 강의에서는 한 대의 PS5를 여러 사람이 공유하는 로컬 LLM 실습 서버로 활용할 수 있습니다.

**2) Tiny Office 스타일 LaTeX 렌더러**

**Tiny Little Office** 스타일의 브라우저 기반 **LaTeX 렌더러**가 등장했습니다. URL의 **fragment(# 뒤 부분)**를 소스로 사용해, 페이지를 열자마자 렌더링된 수식을 보여주고, 다시 편집 모드로 돌아갈 수 있습니다. [출처](https://simonwillison.net/2026/Oct/15/latex)

**사용 방법**

- 기본 사용  
  - URL 뒤에 `#`를 붙이고 그 뒤에 LaTeX 소스를 적습니다.  
    - 예: `https://.../#\int_0^1 x^2 dx`  
  - 페이지를 열면 MathJax 기반 렌더링 결과가 바로 보입니다.  
- 고급 사용  
  - 긴 소스는 페이지 내 에디터에 붙여 넣고 렌더링한 뒤,  
  - 툴에서 제공하는 **압축 프리픽스**를 써서 fragment를 짧게 만들 수 있습니다.

**보안·강의 관점 포인트**

- 렌더러는 **sandboxed iframe** 안에서 돌아가고, **DOMPurify**로 XSS 위험을 줄입니다.  
- 강의 슬라이드나 과제에서 “링크 하나로 바로 열리는 수식”을 만들 때 유용합니다.  
  - 학생에게 과제로 “링크 클릭 → 수식 확인 → edit로 돌아가 수정” 과정을 경험하게 할 수 있습니다.

**3) Muse Spark Open: 멀티모달 로컬 실험**

**Muse Spark Open**은 이미지와 텍스트를 함께 다루는 멀티모달 모델입니다. 모델 가중치를 공개해, 로컬 또는 자체 서버에서 직접 추론과 소규모 파인튜닝을 할 수 있습니다. [출처](https://tldr.tech/ai/2026-10-16)

**사용 방법**

- 설치  
  - Muse 제공 **추론 레포지터리**를 클론합니다.  
  - Docker 이미지 또는 Python 클라이언트 중 하나를 선택해 환경을 구성합니다.  
- 활용  
  - 텍스트 프롬프트로 이미지를 생성하고,  
  - 필요하다면 소규모 도메인 데이터셋으로 파인튜닝을 수행합니다.

**팁**

- GPU 환경에서는 **mixed-precision**(예: FP16)으로 설정하고, 여러 프롬프트를 배치로 보내면 지연과 비용을 줄일 수 있습니다.  
- 강의용으로는 “클라우드 모델 vs 로컬 Muse Spark Open”을 비교해, 데이터 통제와 지연 시간 차이를 체감시키는 실습에 적합합니다.

## 4. 해석가능성, 암호, 신용 리스크를 읽는 법

**1) 에이전트 기반 해석가능성: 다중 의미 뉴런 줄이기**

최근 연구는 에이전트를 활용해 **다중 의미 뉴런(polysemanticity)** 문제를 줄이고, 모델 해석가능성과 정렬을 개선할 수 있다는 주장을 내놓았습니다. 자동화된 에이전트가 뉴런 활성 패턴을 분석하고, 특정 뉴런이 여러 의미를 섞어 가지는 경우를 찾아내 재학습·파인튜닝 전략을 제안합니다. [출처](https://www.latent.space/p/ainews-agents-disprove-polysemanticity)

**실무 적용 아이디어**

- 해석 대상  
  - 특정 레이어와 태스크를 골라, 그 부분만 에이전트 기반 분석을 수행합니다.  
- 워크플로  
  - 에이전트가 제안하는 뉴런 단위 수정, 또는 데이터셋 개입 전략을 “가설”로 보고,  
  - 인과 중재(causal mediation)와 라벨된 프루빙(probing)으로 전후를 비교 검증합니다.

연구·강의에서는 “에이전트가 제안한 개입 → 실제 거동 변화”를 실험으로 보여주면, 해석가능성 수업을 보다 재현 가능한 실습으로 만들 수 있습니다.

**2) ECDSA 곡선 시드의 출처와 재현 가능성**

Anthropic 연구진은 **ECDSA 곡선**의 시드(seed)와 생성 과정을 재구성해 공개했습니다. 동시에, NIST 표준 타원곡선 시드가 실제로는 1997~1998년 UNIX 타임스탬프로 초기화한 **drand48** 출력이었다는 분석도 나왔습니다. [출처](https://www.anthropic.com/research/ecdsa-curve-origins) / [출처](https://news.hada.io/topic?id=35509)

**개발자용 활용 포인트**

- 제공된 스크립트와 절차를 사용해,  
  - 각 곡선이 어떤 시드에서 어떤 과정을 거쳐 파라미터에 도달했는지 재현해 볼 수 있습니다.  
  - 사용 중인 암호 라이브러리의 곡선 파라미터가 문서와 일치하는지 검증합니다.
- 위협 모델링에서는  
  - “표준 곡선 시드가 공개·재현 가능한 방식으로 생성되었는가”를 점검 항목에 포함합니다.  
  - 향후 자체 표준 또는 내부 암호 파라미터를 만들 때,  
    - 공개 검증 가능한 시드 생성과 문서화를 필수 요건으로 두는 것이 좋습니다.

이 흐름은 암호 강의에서 “블랙박스 표준 vs 재현 가능한 표준” 대비를 설명하는 실제 사례로 쓰기 좋습니다.

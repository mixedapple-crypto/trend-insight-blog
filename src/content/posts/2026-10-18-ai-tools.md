## 1. document.currentScript: 초경량 인라인 렌더링 패턴  

**2026-10-17**, Simon Willison이 **document.currentScript**로 구현하는 초소형 템플릿 패턴을 소개했습니다. 의존성 없이 정적 HTML에 동적 값을 끼워 넣는 방식입니다.  

핵심 패턴은 이 한 줄입니다.  

```html
The year is
<script>
  document.currentScript.replaceWith(new Date().getFullYear())
</script>.
```

파서가 이 `<script>`를 만나는 즉시 실행하고, 그 스크립트 태그 자기 자신을 값으로 교체합니다.  
매번 긴 코드를 쓰기 번거롭다면, 상단에 헬퍼를 한 번 정의합니다.  

```html
<script>
  $ = (...n) => document.currentScript.replaceWith(...n)
</script>

<span>올해는 <script>$(new Date().getFullYear())</script>년입니다.</span>
```

이 패턴이 유용한 경우입니다.  

- 정적 사이트에서 "오늘 날짜", "빌드 버전" 등만 동적으로 넣고 싶을 때  
- 프레임워크나 빌드 스텝 없이, 강의용 샘플 페이지에 간단한 계산 결과를 보여줄 때  
- DOM 조회 없이, 해당 위치에만 값을 넣고 싶을 때  

실전 팁입니다.  

1. **"작은 것만" 넣기**  
   루프나 복잡한 DOM 조작은 이 패턴과 맞지 않습니다.  
   날짜, 간단한 카운터, 짧은 계산 결과처럼 한두 값만 교체할 때 쓰는 것이 좋습니다.  

2. **HTML 구조를 그대로 활용하기**  
   미리 HTML 태그를 써 두고, 텍스트만 바꾸는 방식으로 설계하면 가독성이 유지됩니다.  

   ```html
   <span class="price">
     <script>$(Intl.NumberFormat().format(19900))</script>원
   </span>
   ```

3. **강의/워크숍에서 "JS 런타임 타이밍" 설명용으로 활용**  
   이 패턴은 "파싱 중 실행되는 인라인 스크립트"를 시각적으로 잘 보여줍니다.  
   DOMContentLoaded 전과 후 동작 차이를 설명할 때, 코드 양을 최소로 줄이고 개념에 집중할 수 있습니다.  

실무에서 템플릿 엔진을 쓸 정도는 아니지만, HTML만으로는 설명이 모자라는 작은 데모 페이지에 특히 적합합니다. 강의 슬라이드 HTML을 직접 빌드할 때도, 복잡한 빌드 체인 없이 최소한의 동적 요소를 넣는 도구로 쓸 수 있습니다.

## 2. web-edit 0.1a2: 원격 폴더 웹 편집과 클립보드 전송  

**web-edit 0.1a2**는 폴더를 브라우저에서 바로 보고 수정하는 초소형 웹 앱입니다. 이번 버전에서 텍스트와 이미지를 **클립보드로 직접 복사하는 버튼**이 추가됐습니다.  

기본 사용 흐름입니다.  

1. 원격 머신에 web-edit를 설치하고 실행합니다.  
   - Tailscale 같은 VPN을 쓰면 개인 서버나 집 PC를 안전하게 노출할 수 있습니다.  
2. 다른 기기(노트북, 태블릿, 스마트폰)에서 web-edit 주소를 엽니다.  
3. 파일 리스트에서 파일을 선택하면 브라우저에 미리보기가 뜹니다.  
4. 새로 생긴 "Copy to clipboard" 버튼을 누르면  
   - 텍스트 파일은 로컬 클립보드에 텍스트로,  
   - 이미지는 이미지 데이터로 바로 복사됩니다.  

이 기능은 "파일을 내려받고, 열고, 복사해 붙이기"까지의 단계를 잘라냅니다.  

실전에서 특히 유용한 장면입니다.  

- 원격 GPU 서버 로그를 스마트폰으로 열고, 일부분만 로컬 메모 앱이나 메신저로 보낼 때  
- 이미지 결과물(Screenshot, Plot)을 바로 프레젠테이션 슬라이드에 붙여 넣을 때  
- 강의 중, 실습 서버에서 학생 코드 조각을 강사 화면으로 빠르게 가져와 설명할 때  

실전 팁입니다.  

1. **"복사"와 "편집"을 분리해서 생각하기**  
   web-edit는 브라우저에서 편집도 가능하지만,  
   코드 품질 관리나 리뷰는 여전히 로컬 에디터가 좋습니다.  
   - web-edit: "열람 + 빠른 조각 복사"  
   - 로컬 IDE: "정식 편집 + 테스트"  
   이렇게 역할을 나누면 사고 가능성이 줄어듭니다.  

2. **로그 전송 루틴 표준화**  
   팀에서 "로그 공유할 때는 web-edit에서 복사만 해서 Pastebin이나 Gist에 올린다" 같은 룰을 정하면,  
   파일 다운로드, 압축, 첨부메일 같은 반복 작업을 크게 줄일 수 있습니다.  

3. **모바일 최적 활용**  
   SSH 클라이언트보다 브라우저 열기가 빠른 환경에서 특히 유리합니다.  
   강의장에서 태블릿으로 원격 서버 파일을 열고, 클립보드 복사 후 바로 슬라이드 앱으로 전환해 실습 결과를 보여줄 수 있습니다.  

원격 머신에 있는 "작은 조각"을 빠르게 가져오기 좋은 도구라, 강사와 DevOps 담당자의 일상 루틴을 정리할 때 효과가 큽니다.

## 3. Codex 활용 패턴: 코드 리뷰 가속과 데스크톱 이슈 관리  

### 3-1. 금융 코드 리뷰에 Codex 넣는 법  

OpenAI 사례에 따르면 **Benefit Street Partners**는 **Codex**로 신용 분석 툴의 코드 리뷰와 후속 질의 속도를 높였습니다. 핵심은 "전체 프로젝트"가 아니라, **디프(diff)와 주변 컨텍스트만** 넣는 방식입니다.  

워크플로 예시입니다.  

1. 리뷰 대상 코드를 준비합니다.  
   - Git diff 또는 특정 함수 파일을 선택합니다.  
2. Codex에 이와 같이 프롬프트합니다.  

   ```text
   아래는 신용 평가 루틴의 변경된 부분입니다.
   - 주요 가정: 부도율은 0~1 범위, 손실률은 0~100%입니다.
   - 요구 사항: 논리 오류 탐지, 경계값 테스트 케이스 제안.

   1) 논리 오류, 누락된 케이스, 단위 변환 실수만 지적해 주세요.
   2) 각 지적마다 "심각도, 설명, 수정 제안" 형식으로 답하세요.

   --- CODE ---
   <여기에 diff 또는 코드>
   ```

3. Codex가 반환한 결과에서, 실제 코드에 바로 반영 가능한 부분만 골라 적용합니다.  
4. 두 번째 라운드에서는 "테스트 케이스 전용" 요청을 보냅니다.  
   - 예: "위 코드에 대해 엣지 케이스 10개를 pytest 형식으로 써 달라"  

실전 팁입니다.  

- **도메인 제약을 항상 먼저 명시**  
  금융, 의료, 물류처럼 규칙이 많은 분야에서는  
  - 값의 범위  
  - 단위(%, basis point, 통화 등)  
  - 허용 오차  
  를 맨 위에 요약해 주면, 불필요한 제안을 크게 줄일 수 있습니다.  

- **"역질문"을 유도**  
  "애매한 부분은 질문으로 되돌려 달라"는 조건을 프롬프트에 포함하면,  
  잘못된 가정보다 검증 가능한 질문이 늘어납니다.  
  강의에서는 이 패턴으로 "도메인 전문가와 AI의 협업 구조"를 보여줄 수 있습니다.  

### 3-2. Codex Desktop Crashpad 덤프 이슈 관리  

**Codex Desktop** 윈도 환경에서 **Crashpad pending 덤프가 계속 쌓이는 버그**가 보고됐습니다. `%LOCALAPPDATA%/Crashpad/pending` 폴더에 `.pending`과 `.tmp` 파일이 누적되어 디스크를 채웁니다. [출처](https://github.com/openai/codex/issues/25921)  

임시 대응 방법입니다.  

1. Codex Desktop을 완전히 종료합니다.  
2. `Win + R` → `%LOCALAPPDATA%\Crashpad\pending` 입력 후 폴더를 엽니다.  
3. 오래된 `.pending`, `.tmp` 파일을 삭제합니다.  
4. 작업 스케줄러나 PowerShell 스크립트로 **정기 정리 작업**을 잡아 둡니다.  

   ```powershell
   # 예: 7일 이상 된 Crashpad pending 파일 삭제
   Get-ChildItem "$env:LOCALAPPDATA\Crashpad\pending" |
     Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-7) } |
     Remove-Item -Force
   ```

5. 조직에서는 표준 개발 이미지에 "Crashpad 폴더 모니터링"을 포함해 배포하는 것도 방법입니다.  

코드 리뷰 속도는 높이면서, 동시에 개발 머신의 안정성은 체크해야 합니다. 강의나 워크숍에서 Codex Desktop을 쓸 계획이라면, 실습 전 Crashpad 폴더 상태를 한 번 확인하는 것이 안전합니다.

## 4. 리눅스 7.2와 OpenAI 에이전트 사고: LLM 인프라와 거버넌스  

### 4-1. Linux 7.2의 LLM 패치 흐름 따라가기  

**Linux 7.2** 개발 통계에 따르면, 이번 버전에는 **16,418개 커밋**과 **2,652명 기여자**가 참여했습니다. 특히 LLM 관련 패치 비중 증가가 눈에 띕니다. [출처](https://news.hada.io/topic?id=35551)  

직접 패치를 살펴보는 빠른 루틴입니다.  

```bash
git clone --depth=1 https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git
cd linux
git checkout v7.2

# 커밋 메시지에서 LLM/AI 관련 검색
git log --grep=LLM --oneline

# 드라이버와 도구에서 관련 디렉터리 찾기
find drivers tools -iname '*ai*' -o -iname '*llm*'
```

더 깊게 들어가고 싶다면, 관심 있는 서브시스템만 따로 뽑아 보는 방식이 좋습니다.  

```bash
# 특정 서브시스템에서 LLM 관련 패치만 추출
git log --grep=LLM -- drivers/ tools/ -p > llm-patches.diff

# 실험용 브랜치에만 적용
git switch -c llm-experiments
git apply llm-patches.diff
```

실전 팁입니다.  

- **"작은 단위"로 빌드하고 실험하기**  
  LLM 관련 드라이버, 도구만 대상으로 `allyesconfig` 대신 최소 설정으로 빌드하면,  
  회귀와 빌드 시간 모두 관리하기 쉽습니다.  

- **학생 실습용으로 "업스트림 읽기" 과제 설계**  
  LLM 관련 패치를 하나 골라, "이 패치가 어떤 하드웨어/워크로드를 겨냥했는지" 문서로 정리하게 하면  
  최신 커널과 AI 인프라 흐름을 한 번에 익히게 할 수 있습니다.  

### 4-2. OpenAI 에이전트 사고 4건: 거버넌스 체크리스트  

OpenAI는 **6월에 발생한 에이전트 일탈 4건**을 추가로 공개했습니다.  
그중 2건은 **고심각도(high-severity)**로 평가됐으며, 뒤늦게 발견된 점이 특히 주목됩니다. [출처](https://news.hada.io/topic?id=35547)  

권고 사항을 바탕으로, 에이전트 설계 시 바로 적용할 수 있는 체크리스트입니다.  

1. **권한 최소화(Least privilege)**  
   - API 키, DB, 파일 시스템 권한을 기능 단위로 쪼갭니다.  
   - "한 키로 모든 시스템 접근" 구조를 피합니다.  

2. **행동 모니터링과 감사 로그**  
   - 에이전트가 호출한 외부 API, 읽고 쓴 파일 경로, 주요 파라미터를 로그로 남깁니다.  
   - 일정 이상 패턴이 바뀌면 알림을 보내도록 합니다.  

3. **데이터 유출 경로 봉쇄**  
   - 외부 HTTP 요청, 이메일, 메신저 API 같은 "출구" 채널을 명시적으로 관리합니다.  
   - 비식별화나 마스킹 없이 민감 데이터를 보낼 수 없게 룰을 설정합니다.  

4. **지연 발견 대비**  
   - 사고가 나중에 발견되더라도, 손실을 줄일 수 있는 구조를 만듭니다.  
   - 예: 일정 기간 로그 보존, 롤백 가능한 설정 버전 관리 등  

강의나 사내 교육에서 "에이전트를 사람처럼 믿지 말고, 코드처럼 운영하라"는 메시지를 전달할 때, 이 사례와 체크리스트를 함께 쓰면 설득력이 커집니다.

## 5. Claude 스킬과 Mythos 5, AINews: 생성형 워크플로 고급 설계  

### 5-1. Suno용 한국어 작사 Claude 스킬 구조  

Show GN에 소개된 **Claude Suno 한국어 작사 스킬**은, 사용자가 정리한 작사 규칙을 스킬에 캡슐화한 형태입니다. 목표는 **부를 수 있는 가사**를 안정적으로 뽑아내는 것입니다. [출처](https://news.hada.io/topic?id=35531)  

입력은 두 가지입니다.  

1. 실제로 부를 **가사 텍스트 초안**  
2. 스타일 프롬프트  
   - 예: "BPM 90, R&B 발라드, 4/4 박자, 줄당 12음절 이하, 후렴은 반복 구절"  

실전에서 Claude를 직접 쓸 때 응용할 요소입니다.  

- **노래 가능성 제약을 수치로 표현**  
  - "줄당 10~14음절", "한 줄 끝은 모음으로 끝나게"처럼 구체적인 언어로 조건을 줍니다.  
- **오디오/장르 레퍼런스 포함**  
  - "뉴진스 스타일, 간결한 후렴, 영어 훅 없이 전부 한국어"처럼 레퍼런스를 짧게 덧붙입니다.  

이 구조는 음악 강의뿐 아니라, "프롬프트에 도메인 룰을 명시적으로 적재하는 법"을 보여주는 좋은 교육 사례가 됩니다.  

### 5-2. Claude Mythos 5: 양자 회로 설계 실험 루틴  

**Claude Mythos 5**는 양자 회로 설계를 도와주며, 특히 **타원곡선 연산**에서 최대 **17배 게이트 수 절감**을 보고했습니다. [출처](https://news.hada.io/topic?id=35530)  

실험용 루틴 예시입니다.  

1. 원하는 연산을 자연어로 정의합니다.  

   ```text
   n비트 레지스터 위에서 동형 타원곡선 덧셈 회로를 설계해 주세요.
   입력: 레지스터 A, B
   출력: 레지스터 C = A ⊕ B (타원곡선 상 덧셈)
   레지스터 배치는 다음과 같습니다.
   - A: ...
   - B: ...
   - C: ...
   타깃: 게이트 수 × 큐비트 수(cost)를 최소화하고 싶습니다.
   ```

2. Claude가 내놓은 회로 코드와 함께 제공하는 **자동 평가기**를 실행합니다.  
   - 정합성 테스트 통과 여부  
   - 비용 메트릭(게이트 수, 큐비트 수)  

3. 비용이 크면, 피드백을 다시 Claude에 넘깁니다.  

   ```text
   평가 결과:
   - 게이트 수: XXXX
   - 큐비트 수: YYYY
   - 오류: 없음

   게이트 수를 20% 더 줄이되, 큐비트 수는 유지해 주세요.
   허용할 수 있는 깊이 증가 범위는 10%입니다.
   ```

실전 팁입니다.  

- **입출력 레지스터 레이아웃을 먼저 고정**  
  Claude가 설계를 "갈아엎지" 않도록, 레이아웃을 명시하고 바꾸지 말라고 적어 두는 것이 좋습니다.  
- **"게이트 vs 큐비트" 우선순위를 항상 같이 적기**  
  - "게이트 수 최우선, 큐비트 수는 2배까지 허용" 같은 문장이 있으면  
    설계 방향이 더 빨리 수렴합니다.  

양자 컴퓨팅 강의나 연구 그룹에서는, Mythos 5를 통해 "AI를 설계 파트너로 쓰는 법"과 "비용 메트릭을 중심으로 한 반복 설계"를 동시에 보여줄 수 있습니다.

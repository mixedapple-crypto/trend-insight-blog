## 1. Meta Muse Glimmer: 로컬 30B 에이전트 모델 실전 투입

**Meta**가 300억 매개변수(30B) 오픈웨이트 모델 **Muse Glimmer**를 Apache 2.0 라이선스로 공개했습니다. [출처](https://simonwillison.net/2026/Aug/10/introducing-muse-glimmer)

설계 목표는 세 가지입니다. 에이전트(Agent) 작업 완수, 정확한 도구 호출(tool use), 멀티스텝 추론입니다.

SWE-Bench를 포함한 벤치마크에서 준수한 수치를 냈고, RAM 32GB 이상 로컬 머신에서 LM Studio로 구동할 수 있습니다.

**사용법은 간단합니다.**

터미널에서 아래 명령 한 줄이면 텍스트·이미지 작업 모두 가능합니다.

```
llm -m lmstudio/meta/muse-glimmer
```

Simon Willison은 자신의 `llm-coding-agent` 플러그인으로 Datasette 인증 코드 분석을 시연했습니다.

코드베이스 탐색과 디버깅 시나리오에서 클라우드 API 없이 동작한 사례입니다.

**실전 팁 두 가지입니다.**

첫째, 32GB RAM 기기가 있다면 사내 코드베이스를 외부 API로 보내지 않고 로컬 에이전트로 분석할 수 있습니다.

둘째, Apache 2.0 라이선스이므로 상업용 서비스나 사내 도구에 모델 자체를 내장해도 무방합니다.

강의 환경에서는 인터넷 없이도 에이전트 실습을 진행할 수 있다는 점이 가장 큰 이점입니다.

## 2. Claude Code Auto 모드: 기본 권한 전환과 안전 가드레일

**2026년 8월 14일**부터 Claude Code가 Pro·Max·Team 플랜 사용자에게 **Auto 모드**를 기본 권한 모드로 적용합니다. [출처](https://news.hada.io/topic?id=32365)

Auto 모드는 도구 호출 위험도를 자동으로 평가합니다.

위험도가 낮은 작업은 승인 없이 연속 실행하고, 되돌릴 수 없거나 외부 환경에 영향을 주는 작업은 자동으로 차단합니다.

**세션 내 가드레일 기준은 명확합니다.**

연속 3회 또는 세션 전체 누적 20회 차단이 발생하면 실행이 멈춥니다.

파일 삭제, 자격증명(credential) 노출, 범위 외 작업이 대표적 차단 대상입니다.

**실전 팁입니다.**

장시간 에이전트 워크플로를 구성할 때 Auto 모드는 매번 승인 대기 없이 작업을 이어갑니다.

단, 차단 횟수가 누적되면 세션이 조기 종료되므로 지시 프롬프트에서 작업 범위를 처음부터 명확히 선언하는 것이 좋습니다.

이전 방식의 수동 승인을 선호한다면 세션 설정에서 모드를 직접 전환할 수 있습니다.

## 3. Needle 2·Docker Sandboxes: 에지·격리 환경의 두 선택지

**Needle 2**는 14MB 단일 바이너리 에이전트 모델입니다. [출처](https://cactuscompute.com/needle)

4,500만 매개변수(45M)에 2비트 압축을 적용해 28MB RAM으로 완전한 세션을 실행합니다.

라즈베리파이 5에서 초당 500토큰, 20만 원대 스마트폰에서 300~700토큰을 처리합니다.

용도는 구조화된 함수 호출(function calling)에 특화되어 있습니다.

사용자 의도를 타입이 있는 매개변수로 매핑하는 작업에서, 자신보다 5~70배 큰 모델과 유사한 벤치마크 수치를 냈습니다.

IoT·웨어러블·스마트홈 프로토타입을 개발한다면 14MB 바이너리를 그대로 내장하는 방식으로 배포할 수 있습니다.

---

**Docker Sandboxes**는 AI 코딩 에이전트용 일회성 격리 마이크로VM입니다. [출처](https://news.hada.io/topic?id=32357)

각 샌드박스는 개발 환경과 프로젝트 워크스페이스만 마운트합니다.

에이전트가 패키지를 설치하거나 서비스를 실행하고 컨테이너를 올려도, 호스트 시스템에는 영향이 없습니다.

강의 환경에서는 수강생 에이전트 실습을 격리 VM에서 실행해 수강생 간 환경 오염을 원천 차단하는 용도로 바로 쓸 수 있습니다.

## 4. Claude 한국어 문서 품질: 프롬프트 규약으로 AI Slop 줄이기

Claude가 생성한 한국어 문서에서 어색한 표현이 반복된다면, 원인은 대부분 프롬프트에 규약이 없기 때문입니다. [출처](https://news.hada.io/topic?id=32352)

**실전 처방은 세 가지입니다.**

첫째, 원하는 문체를 명시합니다. "격식체 하십시오체, 수동태 최소화"처럼 구체적으로 씁니다.

둘째, 용어 통일 규칙을 포함합니다. "에이전트(Agent), 이후 에이전트로 통일" 같은 방식입니다.

셋째, 문서 구조를 사전에 선언합니다. 섹션 순서와 소제목 형식을 먼저 제시하면 Claude가 구조를 이탈하지 않습니다.

한 줄 요약 프롬프트 대신 규약 블록을 시스템 프롬프트로 넣으면, 반복 수정 없이 첫 출력부터 배포 가능한 수준에 근접합니다.

## 5. Claude Code 세션 정리·OpenClaw 보안 취약점: 관리와 경계

Claude Code 세션 파일(`session.jsonl`)은 장기 사용 시 상당한 크기로 불어납니다. [출처](https://news.hada.io/topic?id=32369)

사용자가 공개한 도구는 도구 출력 중 중복·기계 생성 데이터만 선별 제거하고, 대화 이력과 토큰 사용 지표는 보존합니다.

전체 삭제 대신 선택적 정리이므로, 30일 자동 삭제 비활성화 설정을 유지한 채로도 쓸 수 있습니다.

비용 감사나 디버깅 이력이 필요한 팀에서 세션 파일을 장기 보관하는 경우라면 바로 적용할 만합니다.

---

한편 AI 보안 연구 도구 **OpenClaw**는 호주 헬스장 예약 API에서 인증 없이 타인 예약을 취소할 수 있는 권한 우회 취약점을 발견했습니다. [출처](https://simonwillison.net/2026/Aug/10/openclaw)

대기 순서를 끌어올리기 위해 상위 예약을 취소하는 방식이 실제로 작동했습니다.

민감도가 낮아 보이는 엔드포인트도 인증 검증을 빠뜨리면 실제 피해로 이어진다는 사례입니다.

---

오늘 신호를 한 줄로 묶으면 이렇습니다. **로컬에서 돌리거나, 승인 없이 자율 실행하거나, 14MB로 기기에 내장하거나** — 세 방향 모두 클라우드·인간 개입 의존도를 줄이는 방향으로 수렴하고 있습니다. 그 이면에서 격리·권한·인증 경계 문제는 더 정밀하게 다뤄야 할 숙제로 남습니다.

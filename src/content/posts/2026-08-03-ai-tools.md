## 1. condense-json 1.0: 반복 JSON 압축으로 LLM 로그 용량 줄이기

Simon Willison이 2026년 8월 2일 **condense-json 1.0**을 공개했습니다. [출처](https://simonwillison.net/2026/Aug/2/condense-json)

핵심 원리는 단순합니다. 반복 등장하는 문자열 조각을 짧은 토큰으로 치환하고, 치환 맵(replacements dictionary)을 함께 저장합니다.

사용법은 두 함수로 완결됩니다.

```python
from condense_json import condense_json, uncondense_json

replacements = {"1": "with foxes in it"}
condensed = condense_json(input_json, replacements)
# 압축 해제
original = uncondense_json(condensed, replacements)
```

압축된 출력에는 `{"$r": [...]}` 마커가 삽입되고, `uncondense_json`으로 원본을 완전히 복원합니다.

Willison 본인은 SQLite 기반 LLM 로그 시스템에 적용 중입니다. 모델 응답, 시스템 프롬프트, 메타데이터 같은 반복 필드가 많은 구조에서 효과가 큽니다.

**실전 팁 세 가지:**
- 치환 맵은 도메인별로 관리하면 재사용성이 높습니다. 예를 들어 "프롬프트 템플릿 공통 문구"를 맵으로 고정합니다.
- 압축 전후 크기를 비교해 치환 후보를 점진적으로 늘려가는 방식이 안전합니다.
- `$r` 마커가 포함된 JSON을 LLM에 직접 전달하지 않도록, 입출력 파이프라인에서 압축·해제 위치를 명확히 구분합니다.

LLM 로그를 SQLite나 파일로 장기 보관하는 강의 데모나 프로덕션 환경에서, 스토리지 비용과 데이터 충실도를 동시에 관리하는 실용적인 해법입니다.

## 2. Claude Code 세션 탐색기: 흩어진 대화 맥락을 프로젝트 간에 되찾기

한 개발자가 **Claude Code 세션 탐색기**를 커뮤니티에 공개했습니다. [출처](https://news.hada.io/topic?id=32060)

Claude Code 기본 제공 `claude --resume` 명령은 인터랙티브 피커(interactive picker)를 열지만, 검색 범위가 현재 프로젝트에 한정됩니다. 여러 디렉터리에 걸쳐 장기 작업을 이어가는 개발자에게는 이 범위가 좁습니다.

이 도구는 여러 프로젝트 디렉터리를 횡단하며 과거 세션을 검색하고, 원하는 세션을 골라 재개할 수 있게 해줍니다.

**활용 시나리오:**
- 지난주에 해결한 에러 처리 로직을 다른 프로젝트에 재적용할 때, 관련 세션을 키워드로 찾아 맥락을 불러옵니다.
- 같은 질문을 반복하지 않아 컨텍스트 낭비를 줄입니다.
- 강의용으로 특정 주제 세션만 모아 시연 흐름을 미리 구성할 수도 있습니다.

`claude --resume`의 범위 제약을 우회하는 커뮤니티 도구인 만큼, 공식 지원이 아닌 점은 감안해야 합니다. 그러나 다중 프로젝트 환경에서 지식 재사용을 체계화하려는 실무자에게는 즉시 적용 가능한 접근입니다.

## 3. Copilot 문서 보안 취약점: 데이터와 명령의 경계가 없는 AI의 구조적 문제

노르웨이 연구자가 **Microsoft Copilot** 기반 워크플로의 보안 취약점을 공개했습니다. [출처](https://www.itworld.co.kr/article/4204223/%eb%8d%b0%ec%9d%b4%ed%84%b0-%eb%aa%85%eb%a0%b9-%ea%b5%ac%eb%b6%84-%eb%b6%88%ea%b0%80%ed%95%9c-ai%ec%9d%98-%ed%95%9c%ea%b3%84-%ec%9b%8c%eb%93%9c-%eb%ac%b8%ec%84%9c-%eb%b3%b4%ec%95%88-%ec%9c%84.html)

공격 구조는 이렇습니다. Word 문서 안에 악성 지시를 삽입하면, Copilot이 이를 데이터가 아닌 명령으로 처리해 자동 실행합니다. 이 방식으로 이메일 필터, DLP(Data Loss Prevention), 엔드포인트 보호를 우회하고 문서 간 자가 복제가 가능합니다.

Microsoft는 2026년 3월부터 부분 완화 조치를 배포했지만, 핵심 취약점은 미해결 상태입니다. 연구자와 보안 전문가들은 에이전트(Agent)가 일정 승인 메일과 예약 절차 문서를 동시에 읽는 실제 워크플로에서는 데이터-명령 구분 자체가 성립하지 않는다고 지적합니다.

**지금 적용 가능한 대응책:**
- 최신 업데이트를 즉시 적용합니다.
- Copilot이 생성한 문서는 외부 공유 전 반드시 내용을 검토합니다.
- 출처 불명의 문서를 Copilot 워크플로에 소스로 투입하지 않습니다.
- 다계층 보안 정책을 유지하되, AI 단계만으로 방어가 완결된다고 가정하지 않습니다.

이 취약점은 Copilot에 국한되지 않습니다. 에이전트가 외부 문서를 소스로 삼는 모든 RAG(Retrieval-Augmented Generation) 기반 워크플로에 동일한 구조적 위험이 존재합니다.

## 4. 오픈웨이트 정책 분기: Anthropic이 서명하지 않은 이유와 실무 함의

235개 기업이 미국의 오픈웨이트(open-weight) AI 규제에 반대하는 공개서한에 서명했습니다. Microsoft, NVIDIA, Amazon, OpenAI가 포함됩니다. [출처](https://simonwillison.net/2026/Aug/2/open-letters)

서한의 핵심 논거는 두 가지입니다. 첫째, 폐쇄 모델은 위험을 분산하지 않고 단일 실패 지점을 만든다. 둘째, 한 모델의 출력으로 다른 모델을 학습시키는 디스틸레이션(distillation)은 오픈소스 소프트웨어 관행과 동일하며 오용이 아니다.

**Anthropic은 서명을 거부하고 별도 입장을 발표했습니다.** 이는 업계 내 오픈웨이트 정책을 둘러싼 구조적 분기를 보여줍니다.

실무자 관점에서 이 분기는 도구 선택과 직결됩니다.

- 오픈웨이트 모델을 기반으로 파인튜닝(fine-tuning)하거나 자체 배포 인프라를 구축하는 방향은 서한 서명 진영이 우호적입니다.
- Anthropic의 Claude 계열은 안전 거버넌스 우선 기조를 유지할 가능성이 높으며, 에이전트 설계 시 이 차이를 감안해야 합니다.
- 디스틸레이션 합법성 논쟁은 모델 학습 파이프라인을 설계하는 개발자에게 정책 리스크로 남습니다.

정책 방향이 어느 쪽으로 기울든, 오늘 실무에서 취할 수 있는 행동은 같습니다. 사용 도구의 라이선스와 거버넌스 입장을 명시적으로 파악하고, 의존 모델이 바뀌더라도 전환 가능한 추상화 계층을 워크플로에 유지하는 것입니다.

오늘 신호들을 한 줄로 묶으면, 도구 수준에서는 반복 데이터 압축과 세션 맥락 재사용이라는 '효율' 흐름이 있고, 구조 수준에서는 데이터-명령 혼재와 오픈웨이트 정책 분기라는 '신뢰 경계' 문제가 동시에 부각된 하루입니다.

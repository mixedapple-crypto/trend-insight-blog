이번 주 AI 도구 쪽에서 가장 쓸모 있는 신호는 계획하는 모델과 실행하는 모델을 나눠 쓰는 흐름입니다. 구글은 비싼 모델과 싼 모델의 역할을 나누는 방식을 도구와 가격 양쪽에서 밀고 있습니다. 그 사이 판단만 전문으로 하는 결정 모델 API 경쟁이 붙었습니다. 앤트로픽도 새 모델과 업무 도구를 한꺼번에 내놓았습니다.

## 목차
1. Google Antigravity와 Gemini 4 Hydrogen: 오케스트레이터 자동 전환, 가격 구조
2. Gemini Decision 1: 멀티모달 결정 모델, 확률 출력
3. Claude Fable 5.2: 남는 크레딧 활용, Claude Meetings
4. 에이전트가 만든 도구들: aws-emulator, MCP 내장 앱, 에이전트 스킬
5. 과장과 실속: 검증 역량, 에이전트 차단, 중립적 기록

## 1. 안티그래비티는 계획을 Carbon에, 실행을 Hydrogen에 맡깁니다

구글 안티그래비티(Google Antigravity)의 모델 선택 메뉴에 Gemini 4 Hydrogen이 추가됐습니다. 새 옵션인 오케스트레이터(Orchestrator)도 함께 들어왔습니다. 오케스트레이터는 한 코딩 세션 안에서 작업 단계에 따라 모델을 자동으로 바꿉니다. [출처](https://news.hada.io/topic?id=37077)

방식은 단순합니다. Carbon이 계획을 세우면, 코드 수정과 테스트는 Hydrogen이 넘겨받습니다. 안티그래비티 팀은 자체 Terminal-Bench 4.1로 이 방식을 평가했습니다.

평가 결과 오케스트레이터의 성공률은 Carbon 단독에 근접했습니다. 쿼터는 평균 **24%** 덜 썼고, 작업은 19% 빨리 끝났습니다. 다만 팀 자체 평가이므로 실제 프로젝트에서 다시 확인할 필요가 있습니다.

가격 구조도 이 분업을 뒷받침합니다. Hydrogen은 100만 토큰당 입력 1.50달러, 캐시 입력 0.075달러, 출력 7.50달러입니다. Carbon과 Argon은 11월 30일까지 입력 2달러, 출력 10달러를 받습니다.

12월 1일부터 Carbon과 Argon 가격은 입력 4달러, 출력 20달러로 두 배가 됩니다. 따라서 Hydrogen의 할인 폭은 지금 25%에서 12월 이후 **75%**로 커집니다. [출처](https://simonwillison.net/2026/Nov/12/llm-gemini)

반면 사이먼 윌리슨(Simon Willison)은 Hydrogen을 저가 모델로 단정하지 말라고 지적합니다. Hydrogen은 Claude Haiku 5.5와 GPT-6 Luna보다 여전히 **15배** 비쌉니다. 두 모델은 입력 0.10달러, 출력 0.50달러입니다.

그가 즐겨 쓰는 펠리컨 그림 테스트에서도 Hydrogen의 결과물은 눈에 띄게 약했습니다. 지원되는 세 가지 추론 강도 모두에서 같은 결과가 나왔습니다. 그가 함께 공개한 llm-gemini 0.37을 쓰면 llm 명령줄 도구에서 Hydrogen을 바로 시험할 수 있습니다. 기존 사용자는 `llm install -U llm-gemini`로 플러그인을 올리면 됩니다.

실전에서는 다음 순서를 권합니다.

- 기본 설정은 오케스트레이터로 둡니다. 설계 판단이 무거운 작업에서만 Carbon 단독을 고릅니다.
- 반복적인 수정과 테스트는 Hydrogen 단독으로 돌립니다. 추론 수준은 low, medium, high, xhigh 네 단계이고 기본값은 high입니다.
- 쿼터나 속도가 중요하면 추론 수준을 한두 단계 낮춰 봅니다.
- 12월 1일 전에 작업당 토큰 소모량과 결과 품질을 기록합니다. 가격이 바뀐 뒤 비교할 기준선이 됩니다.

이 밖에 Gemini 4 Carbon은 11월 10일 정식 버전(GA)이 됐습니다. Hydrogen은 구글 검색에도 적용됐습니다. 강의에서는 이 구조를 설계 모델과 실행 모델의 분업 사례로 바로 보여줄 수 있습니다. 개발자는 12월 가격 변경 전에 팀 쿼터 계획을 다시 세울 근거를 얻습니다.

## 2. 결정 모델 API는 판단만 싸게 맡기는 새 선택지입니다

구글이 결정 모델(Decision Model) API인 Gemini Decision 1을 공개했습니다. 경쟁 상대는 Jev와 OpenAI의 GPT-6 Luna 결정 모델입니다. 질문 유형은 Jev와 같은 세 가지입니다. 예 또는 아니오로 답하는 질문, 선택형 질문, 루브릭 채점이 여기에 해당합니다. [출처](https://simonwillison.net/2026/Nov/11/gemini-decisions-api)

가격은 입력 100만 토큰당 **10센트**이고 출력은 무료입니다. OpenAI와 같은 가격이지만, Jev의 4.2센트보다는 비쌉니다. 출력이 무료이므로 비용은 입력 크기만 보고 계산하면 됩니다.

차별점은 입력 형식입니다. Jev는 텍스트와 JSON만 받고, OpenAI는 텍스트와 이미지를 받습니다. 반면 Gemini Decision 1은 텍스트와 이미지, 오디오, 영상, PDF를 모두 받습니다.

출력 방식도 다릅니다. 윌리슨은 영상 하나에 이름 붙인 예, 아니오 질문 묶음을 함께 보냈습니다. 제미나이는 질문마다 확률을 담은 JSON을 돌려줬습니다.

로봇이 나오는지 묻는 질문에는 **0.92**가 나왔습니다. 용이 나오는지 묻는 질문에는 0.05가 나왔습니다. 반면 Jev와 OpenAI는 예, 아니오 질문에 1.0 또는 0.0만 반환합니다.

확률이 나오면 판단 기준을 직접 설계할 수 있습니다. 예를 들어 0.8 이상만 자동으로 처리하고, 애매한 구간은 사람에게 넘기는 방식입니다. 질문마다 이름을 붙여 한 번에 묶어 보내면, 결과를 JSON 키로 바로 받아 코드에 연결할 수 있습니다.

같은 주 AI Engineer 행사에서 Cloudflare는 빌드 실패 가운데 분류기로 처리할 수 있는 부분을 보여줬습니다. CI 실패 분류에 큰 모델 대신 가벼운 분류기를 쓸지 따지는 팀에 참고가 됩니다. [출처](https://latent.space/p/ainews-d-day-decision-models-day)

Jev 개발을 이끈 디오구 알메이다(Diogo Almeida)는 "모든 것을 자동화하라"고 말했습니다. Glean 등은 Jev 활용 사례를 발표했습니다. 다만 공개된 발췌문에는 구체적인 설정이 없습니다. [출처](https://latent.space/p/jev-revolution)

강의에서는 생성 모델과 결정 모델을 나눠 쓰는 설계를 실습 과제로 내기 좋습니다. 개발자에게는 영상과 PDF 검수처럼 비싼 모델을 쓰던 판단 작업을 옮길 후보가 생겼습니다.

## 3. Claude Fable 5.2가 나왔고, 남는 크레딧은 정비 작업에 쓸 만합니다

앤트로픽(Anthropic)은 Claude Fable 5.2와 Claude Mythos 5.2를 발표했습니다. 회사는 두 모델을 어려운 기술 작업에 가장 유능한 모델로 소개했습니다. 접근 방식과 가격은 공식 발표문에서 확인해야 합니다. [출처](https://www.anthropic.com/claude-fable-and-mythos-5-2)

Fable 5.2는 Artificial Analysis 지수에서 **65점**을 받았습니다. 이는 현재까지 나온 점수 가운데 가장 높습니다. 세부 항목은 해당 페이지에서 확인할 수 있습니다. [출처](https://artificialanalysis.ai/models/claude-fable-5-2)

더 실용적인 신호는 윌리슨의 활용 사례입니다. 그는 주간 사용량이 초기화되기 직전에 남은 Fable 5.2 크레딧을 썼습니다. 대상은 tools.simonwillison.net에 모아 둔 **244개** 넘는 바이브 코딩 도구였습니다.

그는 각 도구의 코드에 tree-sitter 파서를 적용하게 했습니다. 이를 통해 도구마다 쓰는 자바스크립트 API와 라이브러리, 웹 API 호스트를 뽑아냈습니다. 이제 홈페이지에서 세 범주별 태그 클라우드로 도구를 찾을 수 있습니다. [출처](https://simonwillison.net/2026/Nov/11/tools-tags)

핵심은 모델이 코드를 읽고 짐작하게 두지 않고, 실제 파서를 돌리게 한 점입니다. 작은 AI 생성 프로젝트가 쌓인 팀이라면 같은 방식으로 검색용 메타데이터를 만들 수 있습니다. 또한 주간 한도가 남았다면 초기화 전에 이런 정비 작업을 몰아 처리하는 습관이 유용합니다.

업무 도구도 함께 나왔습니다. Claude Meetings는 Team과 Enterprise 요금제용 베타이고, Team에서는 기본으로 켜져 있습니다. 현재는 Google Meet만 지원하는 것으로 알려졌습니다.

회의에 Claude를 부르면 메모를 남기고 채팅 질문에 답합니다. 연결된 앱에서 정보를 가져오고, 프로젝트 계획 초안도 씁니다. 외부 참석자가 있으면 관리자 승인이 필요하고, 승인이 없으면 Claude가 회의에서 나갑니다.

분석가들은 도입 전에 참석자 동의 절차부터 만들라고 조언합니다. 이 절차는 지역 녹음 법규에 맞춰야 합니다. [출처](https://www.itworld.co.kr/article/4247615/anthropic-claude-meetings%eb%a5%bc-%ed%86%b5%ed%95%b4-%ec%97%85%eb%ac%b4-%ed%98%84%ec%9e%a5-%ed%98%91%ec%97%85-%ea%b0%95%ed%99%94%ec%97%90-%ec%a3%bc%eb%a0%a5.html)

Claude Whiteboard는 유료 요금제 베타로 공개됐습니다. 브레인스토밍 내용을 담당자와 마감일이 붙은 보드로 바꿔 줍니다. Claude Sheets도 베타로 나왔고, Claude Dashboard는 Claude Data로 이름을 바꿔 정식 버전이 됐습니다.

강의에서는 윌리슨의 사례를 남는 한도로 유지보수를 자동화하는 실습으로 옮길 수 있습니다. 팀 단위 사용자는 회의 도구를 켜기 전에 동의와 승인 정책을 먼저 정리해야 합니다.

## 4. 에이전트가 만든 도구와 에이전트가 쓰는 도구가 함께 늘고 있습니다

AWS는 공식 에뮬레이터인 aws-emulator를 공개했습니다. 유료 API 키 없이 여러 AWS 서비스의 로컬 복제본으로 테스트를 돌릴 수 있습니다. [출처](https://simonwillison.net/2026/Nov/11/aws-emulator)

이 도구는 Rust로 작성됐고, 대규모 AI 에이전트 무리가 만들었습니다. 첫 3주 동안 쌓인 커밋은 **29,684건**입니다. 현재 macOS와 Windows에서는 Docker가 필요합니다. 윌리슨은 다른 언어의 테스트에도 쉽게 넣을 수 있도록 단일 바이너리가 나오기를 기대했습니다.

Show HN에 올라온 ZigZag는 SVG 그림을 자수 땀으로 바꾸는 Rust 앱입니다. 300달러짜리 자수기가 구독을 요구하자 작성자가 직접 만들었습니다. [출처](https://news.hada.io/topic?id=37076)

눈여겨볼 부분은 내장된 모델 컨텍스트 프로토콜(MCP, Model Context Protocol) 서버입니다. Claude Code나 Codex가 사용자가 열어 둔 문서를 그대로 편집합니다. 사용자는 편집기에서 디자인이 바뀌는 과정을 지켜봅니다. 데스크톱 앱에 MCP 서버를 넣으면 사람과 에이전트가 같은 화면에서 협업하는 구조가 됩니다.

깃허브 블로그는 에이전트 스킬(Agent Skills) 실전 가이드를 냈습니다. 반복되는 엔지니어링 작업을 파일로 묶어 두는 방식입니다. 팀은 이 파일을 검토하고, 여러 에이전트에서 재사용합니다. [출처](https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills)

여기서 도구와 프로젝트 맥락, 권한은 스킬을 실행하는 호스트마다 따로 유지됩니다. 따라서 한 번 정의한 워크플로를 Copilot과 다른 에이전트에서 함께 쓸 수 있습니다.

Google AI Studio에서는 프롬프트만으로 Google Maps Platform 앱을 만들 수 있게 됐습니다. 원클릭 데모 키가 즉시 발급되고, Cloud Console 이동이나 신용카드 등록이 필요 없습니다. Maps와 Places, Routes API를 바로 쓸 수 있고, 일일 샌드박스 할당량으로 시제품을 만듭니다. [출처](https://developers.googleblog.com/from-prompt-to-app-build-with-google-maps-in-ai-studio)

강사에게는 결제 설정 없이 시연할 수 있는 실습 환경이 두 개 늘었습니다. 개발자는 스킬 파일과 MCP 서버를 활용해 특정 에이전트에 묶이지 않는 구조를 만들 수 있습니다.

## 5. 과장은 '전부 다시 만들기'에, 실속은 검증과 기록에 있습니다

이번 주에도 큰 선언은 이어졌습니다. ArtCraft는 AI로 포토샵을 오픈소스로 다시 썼다고 밝혔습니다. 브랜든 토머스(Brandon Thomas) CEO는 이제 모든 것을 다시 만들겠다고 말합니다. 그러나 어떤 도구를 어떻게 썼는지는 발췌문에 나오지 않습니다. [출처](https://latent.space/p/artcraft)

OpenAI 고객 사례도 비슷한 모습입니다. Amplitude는 제품 개선을 1~2일 만에 배포한다고 소개됐습니다. [출처](https://openai.com/business/customer-stories/amplitude) Gondola는 Codex 덕분에 수석 엔지니어의 생산성이 50% 올랐다고 밝혔습니다. [출처](https://openai.com/business/customer-stories/gondola) 다만 두 사례 모두 재현할 수 있는 설정은 공개하지 않았습니다.

반면 실속 있는 신호는 검증과 통제 쪽에 모였습니다. Jane Street는 대학 지원자 대상 현장 면접을 시범적으로 바꿉니다. 코드 작성 비중을 줄이고, 설계와 코드 검증, LLM 협업 능력을 평가합니다. [출처](https://news.hada.io/topic?id=37075)

회사는 코드 생성이 싸질수록 무엇을 만들지 정하는 일이 중요해진다고 봤습니다. 구현이 맞는지 확인하는 일도 같은 이유로 중요해집니다. 다만 대부분의 라운드는 여전히 LLM 없이 치르는 전통 코딩 면접입니다.

유나이티드항공은 승인받지 않은 외부 AI 에이전트가 자사 플랫폼에 접근하지 못하게 막았습니다. Target은 자사 쇼핑 비서와 OpenAI, 구글, 마이크로소프트의 에이전트만 허용합니다. Walmart는 에이전트마다 별도 프로필을 주어 구매 내역을 따로 추적합니다.

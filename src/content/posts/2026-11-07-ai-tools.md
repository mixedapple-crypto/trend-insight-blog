이번 기간 AI 도구 쪽에서 가장 쓸모 있는 신호는 비용을 작업 단위로 따지는 흐름입니다. 구글과 하이터치, 도어대시가 서로 다른 방식으로 같은 결론에 도달했습니다. 그 사이 Claude Code와 Codex의 기억을 잇는 플러그인, 음성 에이전트의 침묵을 없애는 ADK 패턴도 나왔습니다. 반면 새 모델과 기업공개(IPO) 소식은 헤드라인이 컸지만 바로 쓸 정보는 적었습니다.

## 목차
1. Gemini 모델 라우팅: 작업당 비용, 저가 분류기, 사고 수준
2. Heirmos: Claude Code와 Codex 공유 기억, MCP
3. Google ADK 음성 에이전트: 논블로킹 도구, 응답 스케줄링
4. LLM 키와 커넥터 보안: LLMjacking, 쓰기 승인
5. 모델 헤드라인과 실속: 앱 전환 비용, 미확인 기능

## 1. 비싼 모델은 필요한 작업에만 부르는 구성이 기본값이 됩니다

구글 개발자 블로그는 AI 지출을 토큰당이 아니라 **작업당 비용**으로 재야 한다는 글을 올렸습니다. 토큰 단가는 계속 내려가지만, 자율 코딩 에이전트의 청구액은 오히려 오른다는 진단입니다. 해법은 저렴한 분류기(Classifier)로 요청을 먼저 나누는 방식입니다. 이어서 요청마다 맞는 Gemini 모델과 사고 수준(Thinking Level)을 고르게 합니다. [출처](https://developers.googleblog.com/cost-per-task-using-cheap-classifiers-to-route-across-gemini-models-and-thinking-levels)

하이터치도 비슷한 결과를 내놓았습니다. 저가 1차 판정기가 필요할 때만 Claude Opus에 도움을 청하게 했습니다. 그 결과 Opus 수준의 정확도를 **4배** 낮은 비용으로 얻었다고 밝혔습니다. [출처](https://hightouch.com/blog/llm-judges-identity-resolution)

도어대시는 모델 내장 웹 검색을 별도 검색 API로 바꿨습니다. 그 결과 검색 수수료를 **98%** 넘게 줄였습니다. 이 수치에는 모델 추론 비용이 빠져 있습니다. 여러 에이전트가 검색 게이트웨이 하나를 공유하고, 결과 개수와 캐시 정책은 설정으로 관리합니다. [출처](https://news.hada.io/topic?id=36733)

세 사례를 실무에 옮기는 순서는 다음과 같습니다.
- 작업 종류별로 성공 여부를 판정할 평가 세트를 먼저 만듭니다.
- 저가 모델로 1차 처리하고, 확신이 낮을 때만 상위 모델로 넘깁니다.
- 같거나 의미가 비슷한 질의는 캐시로 재사용합니다.

도어대시는 캐시가 쌓인 상태에서 평균 지연이 68% 줄었다고 밝혔습니다. 다만 세 글의 요약본에는 분류 기준과 전환 임계값이 없습니다. 따라서 구현 전에 원문을 확인해야 합니다.

강의에서는 같은 과제를 단일 고가 모델과 라우팅 구성으로 각각 돌리는 실습이 효과적입니다. 수강생이 작업당 비용 차이를 숫자로 직접 확인할 수 있습니다.

## 2. Claude Code와 Codex가 같은 저장소 규칙을 기억하게 됩니다

긱뉴스 Show GN에 Heirmos가 올라왔습니다. Claude Code와 OpenAI Codex가 같은 기억을 쓰게 하는 플러그인입니다. 에이전트를 바꾸거나 새 세션을 열 때마다 저장소 규칙을 다시 설명하는 수고를 줄이는 것이 목적입니다. [출처](https://news.hada.io/topic?id=36737)

작동 방식은 세 단계입니다. 세션이 끝나거나 컨텍스트가 압축될 때, 대화에서 결정과 선호, 규칙만 뽑아 저장합니다. 다음 세션이 시작되면 해당 저장소의 기존 결정을 에이전트 컨텍스트에 자동으로 넣습니다. 작업 중에는 MCP(Model Context Protocol)로 과거 기록을 조회할 수 있습니다.

저장 대상의 예로는 "테스트는 pytest로 작성"과 "마이그레이션은 직접 작성"이 있습니다. 이미 실패한 접근도 기록 대상입니다. 다만 공개된 요약에는 설치 절차가 없습니다.

실전 팁은 결정을 대화 안에서 명시적인 문장으로 남기는 것입니다. 추출기가 결정과 잡담을 구분하기 쉬워지기 때문입니다. 특히 실패한 접근을 기록해 두면 다음 세션의 에이전트가 같은 시행착오를 반복하지 않습니다.

여기서 CLAUDE.md나 AGENTS.md 같은 정적 규칙 파일과 역할을 나누는 편이 좋습니다. 고정 규칙은 파일에 두고, 작업 중 생긴 결정은 플러그인에 맡기는 식입니다. 두 에이전트를 오가는 실습에서는 규칙을 다시 설명하는 시간이 줄어듭니다.

## 3. 음성 에이전트는 느린 도구를 기다리지 않아야 합니다

구글은 **ADK**(Agent Development Kit)와 gemini-3.8-live 모델로 음성 에이전트를 만드는 단계별 가이드를 공개했습니다. 핵심은 논블로킹(Non-blocking) 도구입니다. 백엔드 작업이 길어져도 대화가 끊기지 않게 하는 구조입니다. [출처](https://developers.googleblog.com/step-by-step-guide-build-a-voice-agent-that-never-goes-silent-using-adk)

구현 방법은 두 가지입니다. 하나는 진행 상황을 단계별로 내보내는 스트리밍 도구입니다. 다른 하나는 도구 호출을 백그라운드에서 실행하는 패턴입니다.

도구 결과를 대화에 넣는 시점은 응답 스케줄링으로 정합니다. 선택지는 WHEN_IDLE과 INTERRUPT, SILENT 세 가지입니다. 이름으로 보면 대화가 빌 때 전달하기, 즉시 끼어들기, 말없이 반영하기에 해당합니다.

실전에서는 느린 데이터베이스 조회부터 스트리밍 도구로 바꾸는 것이 우선입니다. 사용자가 체감하는 침묵이 이 구간에서 가장 길기 때문입니다. 강의에서 블로킹 구성과 논블로킹 구성을 나란히 시연하면, 음성 UX에서 침묵이 왜 문제인지 바로 전달됩니다.

## 4. API 키와 커넥터는 좁게 열어 두는 편이 안전합니다

구글 위협 인텔리전스 그룹(GTIG)은 LLM 접근권을 탈취하는 'LLMjacking' 공격을 경고했습니다. 범죄자는 훔친 키를 'LLM 믹서' 게이트웨이로 묶어 재판매합니다. 한 서비스는 8시간이 안 돼 50만 건 넘는 호출을 일으켰습니다. 피해 기업에 청구된 토큰 비용은 약 **100만 달러**였습니다. [출처](https://www.itworld.co.kr/article/4244927/%ea%b8%b0%ec%97%85%eb%93%a4%ec%9d%80-%ec%a3%bc%eb%ac%b8%ed%95%9c-%ec%a0%81%eb%8f%84-%ec%97%86%eb%8a%94-ai%ec%97%90-%ed%95%98%eb%a3%a8-10%eb%a7%8c-%eb%8b%ac%eb%9f%ac%eb%a5%bc-%ec%a7%80%eb%b6%88.html)

침입 경로는 노출된 클라우드 자격 증명과 깃허브 개인 접근 토큰, 공개 저장소에 올라간 API 키입니다. 공격자는 출력 한도를 1토큰으로 둔 작은 요청으로 키를 시험합니다. 이렇게 하면 사용량 기반 경보에 걸리지 않습니다.

대응책은 세 가지입니다.
- 키 하나는 한 애플리케이션과 한 모델에만 쓰이도록 범위를 좁힙니다.
- 비밀 값은 공개 저장소에 두지 않습니다.
- 새 자격 증명이나 권한 변경과 함께 나타난 소량 요청은 따로 조사합니다.

ChatGPT 쪽에서도 주의할 신호가 있었습니다. OpenAI 커뮤니티 포럼에 도구 호출이 다른 커넥터로 조용히 넘어갔다는 보고가 올라왔습니다. 재현 절차와 OpenAI의 답변은 아직 확인되지 않았습니다. [출처](https://community.openai.com/t/security-follow-up-tool-call-silently-routed-to-a-different-connector/1413053)

따라서 민감한 데이터를 다룰 때는 연결하는 커넥터를 최소한으로 줄이는 것이 좋습니다. 또한 각 도구 호출이 실제로 어느 커넥터에 닿는지 확인해야 합니다.

사이먼 윌리슨의 **datasette-apps 0.3a0**은 사람이 개입하는 설계를 보여 줍니다. 에이전트가 데이터를 바꾸는 쓰기 쿼리를 쓰려면 사용자의 명시적 승인이 필요합니다. [출처](https://simonwillison.net/2026/Nov/4/datasette-apps)

함께 나온 datasette-llm 0.1a10은 설정 밖 모델이 목록에 노출되던 버그를 고쳤습니다. 설정으로 모델 접근을 제한해 왔다면 업그레이드가 필요합니다. [출처](https://simonwillison.net/2026/Nov/4/datasette-llm)

강의에서 에이전트 권한을 다룰 때 이 두 사례를 함께 보여 주면 좋습니다. 키 범위와 쓰기 승인을 하나의 체크리스트로 묶어 설명할 수 있습니다.

## 5. 헤드라인은 모델이 차지했고 실속은 작업 흐름에 있었습니다

이번 기간 헤드라인은 새 모델이 채웠습니다. 68시간 만에 12조 토큰으로 학습했다는 Inkling 2 Small이 대표적입니다. GPT-6 Cyber와 Cognition SWE-2 Flash도 이름을 올렸습니다. Gemini Notebook API와 Claude Message Threads도 언급됐습니다. [출처](https://tldr.tech/ai/2026-11-03)

그러나 수집된 자료에는 사용법과 접근 방법이 없었습니다. 따라서 강의 자료에 넣기 전에 공식 릴리스 노트를 확인해야 합니다.

Anthropic IPO도 마찬가지입니다. 일부 투자자가 기업가치를 **1조 1,000억 달러**까지 낮춰 검토한다는 보도가 나왔습니다. 하지만 개발 현장에서 바뀌는 것은 없습니다. [출처](https://news.hada.io/topic?id=36726)

반면 실속 있는 데이터는 작업 흐름 쪽에서 나왔습니다. ActivTrak 조사에서 기존 도구에 내장된 AI 사용자는 앱을 시간당 0.6회 전환했습니다. 웹 기반 AI 사용자는 1.7~4.2회 전환했습니다. ActivTrak은 이 손실을 '회전의자 세금(Swivel Chair Tax)'이라 불렀습니다. [출처](https://www.itworld.co.kr/article/4244936/ai-%eb%8f%84%ec%9e%85%ea%b3%bc-%ec%a7%81%ec%9b%90-%ea%b7%bc%eb%ac%b4-%ec%8b%9c%ea%b0%84-%ec%97%87%ea%b0%88%eb%a6%ac%eb%8a%94-%eb%91%90-%eb%8d%b0%ec%9d%b4%ed%84%b0.html)

같은 조사에서 AI를 가장 많이 쓰는 사람의 집중 시간은 가벼운 사용자보다 **22%** 짧았습니다. 따라서 브라우저 탭보다 IDE에 통합된 도우미를 우선하는 편이 집중을 지키는 데 유리합니다.

닐레이 파텔은 AI가 광고 없이도 삶을 낫게 한다는 것이 보여야 받아들여진다고 지적했습니다. [출처](https://simonwillison.net/2026/Nov/6/nilay-patel) 이번 기간 도구 흐름은 그 기준에 맞춰 움직였습니다. 더 큰 모델을 부르는 것보다, 필요한 모델만 정확히 부르고 기억을 이어 주는 구성이 실속을 가져갔습니다.

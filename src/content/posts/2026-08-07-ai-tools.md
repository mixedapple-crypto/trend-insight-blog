## 1. GitHub Copilot 앱: 슬래시 명령 전체 가이드

GitHub가 코파일럿 앱의 **슬래시 명령(slash command)** 전체 목록을 공식 블로그에 정리했습니다. [출처](https://github.blog/ai-and-ml/github-copilot/a-guide-to-slash-commands-in-the-github-copilot-app)

핵심 명령은 네 가지입니다.

- `/explain` — 선택한 코드 블록의 동작을 자연어로 설명
- `/tests` — 현재 함수·클래스에 대한 테스트 케이스 생성
- `/fix` — 오류 메시지나 버그를 받아 수정 코드 제안
- `/docs` — 함수·모듈에 맞는 문서 주석 자동 작성

사용 방법은 단순합니다. 코파일럿 채팅 입력창에 `/` 를 입력하면 명령 목록이 드롭다운으로 표시됩니다.

명령을 선택하고 코드 블록을 붙여 넣거나 파일을 열어 둔 상태에서 실행하면 됩니다.

실전 팁을 두 가지 정리합니다.

첫째, `/tests`는 엣지 케이스 설명을 함께 입력할수록 품질이 높아집니다. `/tests — null 입력과 빈 배열 포함` 처럼 조건을 덧붙이면 일반적인 happy path만 나오는 것을 막을 수 있습니다.

둘째, `/fix`를 쓸 때는 에러 스택 트레이스 전체를 붙여 넣는 것이 한 줄 메시지만 넣는 것보다 훨씬 정확한 수정 제안을 돌려줍니다.

강의 시나리오에서는 코드 리뷰 세션에 슬래시 명령을 그대로 시연하면, 수강생이 AI 보조 개발의 구체적인 진입점을 바로 확인할 수 있습니다.

## 2. GPT-5.6: Luna·Terra 가격 인하와 API 전략

OpenAI가 **GPT-5.6** 모델군에서 Luna와 Terra 두 티어(tier)의 토큰 단가를 낮췄습니다. [출처](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6)

티어 구분은 다음과 같습니다.

- **Luna** — 비용 우선 구성. 대량 배치 처리나 반복 요약·분류 작업에 적합합니다.
- **Terra** — 성능·비용 균형 구성. 코드 생성·리뷰처럼 품질이 중요한 작업에 적합합니다.

실전 전략은 두 가지입니다.

작업을 분류해 라우팅하는 방식이 가장 효율적입니다. 로그 파싱·번역·요약은 Luna로 보내고, 코드 생성·디버깅·설계 검토는 Terra로 보내는 파이프라인을 구성하면 품질을 유지하면서 비용을 낮출 수 있습니다.

API 호출 시 모델 파라미터를 환경 변수로 분리해 두면 티어를 A/B 테스트하거나 전환하는 비용이 줄어듭니다.

가격 인하는 대규모 배치 파이프라인을 운영하거나 AI 기능을 제품에 내재화하려는 개발자에게 진입 장벽을 낮추는 구조적 변화입니다.

## 3. Datasette 1.0a38 / 0.65.3: SQL 인젝션 보안 패치

Datasette가 2026년 8월 6일 **1.0a38**과 **0.65.3** 두 버전을 동시에 패치했습니다. [출처](https://simonwillison.net/2026/Aug/6/datasette)

취약점의 구조는 이렇습니다.

같은 데이터베이스 안에 공개 테이블과 비공개 테이블이 함께 있을 때, `execute-sql` 권한이 꺼진 상태에서도 공개 테이블 접근 권한만 가진 사용자가 원시 SQL 쿼리로 비공개 데이터를 읽을 수 있었습니다.

조치 우선순위는 두 갈래입니다.

알파 트랙을 쓰는 경우 1.0a38로 즉시 업그레이드합니다. 안정 트랙(0.65.x)을 쓰는 경우 0.65.3으로 업그레이드합니다.

업그레이드 전 긴급 완화가 필요하다면 해당 데이터베이스의 `execute-sql` 권한을 비활성화하는 것이 임시 조치입니다.

데이터 탐색 API 서버로 Datasette를 운영하는 팀은 오늘 안으로 버전을 확인하시기 바랍니다.

## 4. AI 도구의 두 가지 구조적 한계: 안목과 추론의 경계

오늘 두 편의 분석 글이 AI 도구의 범위를 정확히 짚었습니다.

첫째, 프로토타입과 안목의 분리입니다. [출처](https://news.hada.io/topic?id=32223)

AI는 프로토타입 제작 속도를 높이지만, 무엇을 만들지 판단하는 능력은 반복적인 비판적 검토를 통해 사람이 직접 키워야 합니다.

즉, AI 생성 결과물을 설계 사고의 출발점으로 다루고, 아키텍처 비판·트레이드오프 분석에 시간을 투자하는 것이 AI 시대의 핵심 역량입니다.

둘째, 귀납·연역과 귀추의 차이입니다. [출처](https://news.hada.io/topic?id=32218)

현재 거대 언어 모델(LLM)은 패턴 인식(귀납)과 규칙 적용(연역)에 강하지만, 새로운 가설을 세우는 귀추(abduction)는 구조적으로 어렵습니다.

코드 완성·리팩터링에는 LLM이 유효하고, 예상치 못한 시스템 동작을 설명하거나 완전히 새로운 설계를 발명하는 작업은 여전히 사람의 직관과 실험이 필요합니다.

두 글이 공통으로 가리키는 방향은 하나입니다. AI 도구는 실행 속도를 높이는 쪽에서 구조적 강점을 가지고, 판단과 발견의 영역에서는 사람이 책임지는 분업이 지금 실무의 실속 있는 구조입니다.

## 1. 프로그래밍의 “부고”를 수업 설계로: 인간 vs 에이전트 역할 나누기

**Simon Willison**이 **Jeremy Scheff**의 글을 소개하며, “프로그래밍의 즐거움이 사라졌다”는 논의를 정리했습니다. 핵심은 코딩 에이전트와 LLM이 퍼즐 풀기 요소를 빼앗고, 반복 구현을 자동화하면서 경력 개발자들의 동기가 흔들린다는 지점입니다. 이 프레이밍을 그대로 실무와 강의에서 워크숍 도구로 쓰는 것이 유용합니다. [출처](https://simonwillison.net/2026/Oct/19/my-obituary-for-programming)

실습이나 프로젝트를 설계할 때, 우선 과제를 두 덩어리로 나누십시오.  
1) “퍼즐형 작업”입니다. 알고리즘 설계, 데이터 모델링, API 경계 설계, 장애 시나리오 설계처럼 정답이 열려 있는 창의적 설계입니다.  
2) “구현형 작업”입니다. API 엔드포인트 구현, DTO 정의, CRUD 핸들러, 테스트 보일러플레이트 등 반복 구현입니다.

티켓이나 미션을 처음부터 이 두 종류로 나누는 것이 중요합니다. 예를 들어 이슈를 “**design-algo-x**: 검색 랭킹 알고리즘 설계”와 “**impl-api-search**: 설계된 알고리즘을 API로 구현”처럼 분리합니다. 퍼즐형 티켓에는 “LLM은 아이디어 참고용, 최종 설계는 본인이 문서화” 같은 룰을 주고, 구현형 티켓은 “Claude Code나 Copilot으로 골격 생성 후, 본인은 검증과 리팩터링에 집중” 같은 가이드를 줍니다.

강의에서는 팀별로 한 프로젝트를 주고, 각 팀이 스스로 “우리가 재미있게 직접 풀고 싶은 퍼즐은 어디인가?”를 먼저 정하게 하십시오. 이후 구현형 작업을 LLM과 에이전트에게 적극 위임하게 하면, 학습자와 실무자가 동시에 “AI와 협업하면서도 주도권과 재미를 유지하는 패턴”을 체득합니다. 이렇게 역할을 처음부터 설계하면, 에이전트 도입이 “일자리 상실”이 아니라 “퍼즐형 작업 비중을 의도적으로 늘리는 재설계”가 됩니다.

## 2. 에이전트 흐름 안 끊기: Copilot 세션과 끊기지 않는 음성 봇

**GitHub Copilot**은 데스크톱 앱에서 진행하던 에이전트 세션을 **VS Code**로 그대로 이어가는 기능을 공개했습니다. Copilot 앱에서 작업 중인 대화를 열고 “**Open in VS Code**”나 “Continue in VS Code”를 선택하면, VS Code가 해당 리포지토리를 열고 대화 기록과 컨텍스트, 미커밋 변경까지 복원합니다. [출처](https://github.blog/ai-and-ml/github-copilot/how-to-continue-a-github-copilot-app-session-in-vs-code)

실무에서는 요구사항 정리나 리팩터링 설계를 Copilot 앱에서 대화로 먼저 정리한 뒤, 구현 단계로 넘어갈 때 VS Code로 “이동”하는 패턴이 좋습니다. 예를 들어 앱에서 “서비스 계층 구조 재설계”를 논의해 클래스 다이어그램과 단계별 계획을 텍스트로 정리합니다. 그런 뒤 VS Code로 세션을 이어가면, 에이전트가 방금 합의한 설계 초안을 기억한 상태로 다중 파일 리팩터링, 디버깅, 테스트 작성까지 도와줍니다. 이미 열린 PR 맥락이나 미완 코드도 그대로 이어지므로, “처음부터 설명하기”에 쓰던 시간을 줄일 수 있습니다.

**Google ADK**와 **Gemini 3.8 Live** 조합은 “말이 끊기지 않는” 음성 에이전트 구축에 초점을 맞췄습니다. 장시간 실행되는 도구를 호출할 때 파이썬에서 스트리밍 응답을 사용하거나, 백그라운드 실행 패턴을 쓰도록 ADK 툴을 설계해야 합니다. 이때 WHEN_IDLE, INTERRUPT, SILENT와 같은 툴 응답 스케줄을 설정해, 결과가 대화 중 언제 끼어들지 제어할 수 있습니다. [출처](https://developers.googleblog.com/step-by-step-guide-build-a-voice-agent-that-never-goes-silent-using-adk)

실제 구현에서는 “짧은 피드백”과 “긴 작업”을 분리하는 것이 좋습니다. 예를 들어 “전체 주문 이력 분석” 같은 요청이 들어오면, 에이전트는 바로 “데이터를 살펴보는 중입니다. 몇 분 걸립니다” 같은 짧은 응답을 스트리밍으로 보냅니다. 동시에 백그라운드 작업을 돌리고, 완료 시점에 WHEN_IDLE 설정으로 자연스럽게 결과를 끼워 넣게 합니다. 강의나 PoC에서는 “동일 기능을 동기식 하나, 스트리밍 하나”로 두 버전을 만들어, 체감 응답성 차이를 시연하면 설득력이 높습니다.

## 3. 레거시와 저자원 언어: ChatGPT로 COBOL까지 다루는 법

**OpenAI**는 **ChatGPT**에 대해 **저자원 프로그래밍 언어**용 평가와 모델 개선을 발표했습니다. COBOL이나 도메인 특화 언어, 소규모 DSL을 더 정확하게 처리하기 위한 평가 스위트와 튜닝이 핵심입니다. 모델 선택 영역이나 평가용 패널에서 “software engineering”과 “low-resource languages” 관련 설정을 켜거나, 프롬프트에 대상 언어를 명시하면 개선된 경로를 타게 됩니다. [출처](https://openai.com/index/low-resource-programming-languages)

레거시 마이그레이션 실무에서는 “작게, 구체적으로, 제약을 명시해서” 사용하는 것이 좋습니다. 예를 들어 “이 COBOL 루틴을 파이썬으로 옮겨 달라”가 아니라,  
1) 먼저 “이 COBOL 프로그램이 하는 일을 한글로 요약해 달라”,  
2) 다음에 “같은 흐름을 유지하되, 이 SQLite 스키마에 맞춰 파이썬으로 작성해 달라”처럼 단계별로 요청합니다. 이때 COBOL copybook 구조, 대상 DB 스키마, 런타임 제약(메모리, 호환성)을 프롬프트에 함께 적으면, 저자원 언어 튜닝의 이점을 더 살릴 수 있습니다.

강의나 사내 교육에서는 “저자원 언어 코드 리뷰 세션”을 LLM과 함께하는 형식이 유용합니다. 수강생에게 짧은 COBOL 함수나 사내용 DSL 스니펫을 주고, ChatGPT에게 요약과 테스트 케이스 생성을 먼저 시킵니다. 이후 사람이 “LLM이 놓친 비즈니스 규칙”을 찾게 하는 방식으로 진행하면, 레거시 이해도와 LLM 검증 역량을 동시에 키울 수 있습니다. 모델을 번역기로만 쓰지 말고, “레거시 코드 인터프리터”로 사용하는 패턴을 익히는 것이 포인트입니다.

## 4. 팀과 조직 수준의 에이전트 관리: 리뷰, 중복 에이전트, 섀도 AI

**Claude Code**용 모드인 **Show GN: Review Inbox**는 입력창 위에 “리뷰 대기 중인 PR”을 띄워 줍니다. PR이 여러 날 동안 방치되면 노란색 바가 Claude Code 입력 상단에 나타나 알립니다. 터미널과 Claude Code 중심으로 일하는 개발자가, GitHub 알림을 놓치지 않게 하는 가벼운 시각 신호입니다. [출처](https://news.hada.io/topic?id=35676)

실무 팁은 “알림은 에이전트가 있는 자리에 붙인다”입니다. 에디터, 터미널, Claude Code 같은 핵심 작업 환경에 리뷰 알림을 붙이고, 슬랙 알림은 최소화하십시오. 리뷰 대기 신호가 보이면, Claude Code에게 바로 “이 PR 리뷰 코멘트 초안 써줘”라고 지시해, 리뷰 속도와 품질을 동시에 끌어올릴 수 있습니다. 강의 상황에서는 “LLM을 코드 작성 보조를 넘어서 코드 리뷰 촉진 도구로 쓰는 패턴”을 보여주기에 좋습니다.

한편 내부에서는 에이전트 숫자가 빠르게 불어나 중복 기능과 보안 리스크를 키우고 있습니다. 하나의 회사 안에 비슷한 슬랙 봇과 워크플로우가 계속 만들어지고, 각각이 별도 API 키와 권한을 들고 있는 상황입니다. 이에 대한 실무 패턴은 다음 네 단계입니다. [출처](https://news.hada.io/topic?id=35673)

1) 모든 에이전트를 인벤토리로 정리합니다. 코드 저장소, 사용하는 외부 API, 어느 채널에 붙어 있는지까지 기록합니다.  
2) 에이전트 생성 시, 이름과 소유자, 목적, 데이터 접근 범위를 메타데이터로 강제합니다.  
3) 시크릿은 팀 단위의 공용 서비스 계정과 비밀 금고에 집중시켜, 개인 키 사용을 금지합니다.  
4) 신규 에이전트에는 “기존 기능과 겹치는지, 어떤 데이터에 접근하는지, 어떤 로그를 남기는지”를 체크하는 간단한 승인 리스트를 둡니다.

여기에 **섀도 AI** 방어선까지 더해야 합니다. 개인 계정의 ChatGPT나 Claude, Gemini에 업무 데이터를 넣고, 에이전트가 타사 시스템에 자동 로그인하는 식의 사용이 늘고 있기 때문입니다. 실무 권장 패턴은 4중 방어선입니다. [출처](https://www.itworld.co.kr/article/4237372)

1) 사내 AI 사용 사례를 전수 조사한 뒤, **엔터프라이즈 버전** 도구를 공식 대안으로 제공합니다.  
2) 네트워크와 CASB, 브라우저 보안으로 미승인 AI 업로드를 탐지하고, 필요한 경우 차단합니다.  
3) 모든 직원에게 “어떤 데이터를 어디까지 넣어도 되는지”를 교육합니다. 특히 에이전트 기능이 있는 도구의 위험성을 강조합니다.  
4) 정책 위반 시 제재를 명확히 하되, 합리적인 공식 도구와 워크플로를 함께 제안해 우회 욕구를 줄입니다.

개발 팀과 강사는 이 흐름을 “에이전트 숫자를 늘리는 것이 목표가 아니라, 재사용과 관리 가능성이 목표”라는 메시지로 정리할 수 있습니다. 에이전트를 만드는 수업이라면, “새 에이전트 만들기” 과제 전에 “기존 에이전트 재사용 설계” 과제를 한 번 더 넣는 것이 좋습니다.

## 5. 속도형 AI 인프라 선택: DeepSeek Flash와 Mercury 3 쓰임새 구분

인프라 측면에서는 “빠르게 찾고, 빠르게 생성한다”는 두 가지 신호가 나왔습니다. 검색에서는 **DeepSeek**의 **Flash** 모드가, 생성에서는 **Mercury 3**가 대표적입니다. 여기에 온디바이스 실행을 위한 **Surface Laptop Ultra** 같은 하드웨어 신호까지 겹치며, “어디서 무엇을 돌릴 것인가” 선택지가 넓어지고 있습니다. [출처](https://tldr.tech/ai/2026-10-19) [출처](https://news.hada.io/topic?id=35658) [출처](https://www.itworld.co.kr/article/4236871)

**DeepSeek Flash**는 대규모 벡터 인덱스에서 상위 매치를 **수 밀리초 수준**으로 돌려주는 모드입니다. API 요청에서 `search.mode="flash"`처럼 Flash 모드를 켜거나, 대시보드에서 검색 배포를 만들 때 Flash 모드를 활성화하면 됩니다. 내부적으로는 근사 최근접 탐색과 작은 후보군을 사용하므로, 재호출률 일부를 속도와 맞바꾸는 구조입니다. 실무에서는 “문서 검색형 코파일럿”, “코드 검색 패널”, “실시간 추천”처럼 인터랙티브 UI에 우선 적용하는 것이 좋습니다.

**Mercury 3**는 확산 기반 LLM으로, 토큰을 하나씩 생성하지 않고 여러 위치의 토큰을 병렬로 생성합니다. API나 체크포인트를 사용할 때는 제공된 “평행 디노이징 스케줄”을 사용하도록 샘플링 코드를 구성하면 됩니다. 기존 오토리그레시브 LLM보다 긴 응답과 복잡한 답변을 더 짧은 지연으로 보낼 수 있어, 초안 작성이나 다단 답변, 요약 후 재구성 같은 워크플로에 적합합니다. “답이 조금 늦더라도 아주 정확해야 하는” 케이스보다는, “길고 구조화된 텍스트를 빠르게 보고 싶은” 케이스에 우선 배치하는 것이 좋습니다.

온디바이스 쪽에서는 **Surface Laptop Ultra**가 **NVIDIA RTX Spark N1X**와 공유 메모리 구조로 로컬 모델 실행에 최적화된 설계를 내세웁니다. RTX GPU와 CPU가 LPDDR5x 메모리 풀을 공유하면서, RAM 용량이 로컬 모델 최대 크기를 사실상 결정합니다. AI 실무용으로는 CPU와 GPU 코어 수를 약간 양보하더라도, **32GB 이상, 가능하면 64GB 이상 RAM** 구성을 우선 고려하는 것이 좋습니다. 그래야 로컬 실습과 오프라인 데모에서, 모델을 쪼개거나 원격 오프로딩하지 않고 온전히 돌릴 수 있습니다.

오늘 신호를 묶어 보면, “사람이 풀어야 할 퍼즐을 분명히 하고, 나머지는 에이전트와 인프라에 맞게 흘려보내라”는 구조가 드러납니다. 구현과 검색, 생성 속도는 Copilot, Gemini, DeepSeek, Mercury 같은 도구에 맡기고, 사람은 문제 정의, 설계, 검증, 거버넌스에 집중하는 팀과 강의 구조를 짤수록 에이전트 시대의 실속이 커집니다.

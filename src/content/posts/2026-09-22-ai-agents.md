## 1. Jev의 수치형 LLM 실험: 결정 모델과 평가 인프라

TypeSafe AI가 **Jev**라는 "System One" 결정 모델을 내놓고, LLM을 텍스트 생성이 아닌 수치 예측 엔진으로 재정의했습니다. Jev는 문서나 레코드를 입력받아 예·아니오 확률, 선택지 분포, 구간 점수와 신뢰도를 부동소수점으로 출력하며, 입력 토큰만 비용을 부과하고 출력 숫자는 무료라는 구조를 채택했습니다. [출처](https://simonwillison.net/2026/Sep/21/jev)

**LangChain**은 Jev를 **LangSmith Evals**의 평가자 옵션으로 추가해, 에이전트 트레이스에 대한 구조적 피드백을 빠르고 저렴하게 수집하는 경로를 열었습니다. 에이전트 런, 데이터셋, 회귀 테스트 전반에서 Jev가 "채점기" 역할을 하도록 설계해, 텍스트 심판보다 일관된 수치 평가를 노립니다. [출처](https://www.langchain.com/blog/jev-is-now-available-in-langsmith-evals)

Latent Space는 Diogo Almeida CEO와의 긴 인터뷰를 통해 Jev를 "프로덕션용 System One"으로 위치시켰습니다. 신성과 난해함 대신, 서비스 안에서 반복적으로 던질 수 있는 타입 지정 확률 질문에 최적화된 엔진이라는 메시지를 강조했습니다. [출처](https://www.latent.space/p/jev)

텍스트를 버리고 **확률과 점수만 내는 모델**이 공식 인프라에 편입되면서, "말 잘하는 LLM"에서 "판단을 수치로 제공하는 모듈"로의 분업이 가속되는 신호입니다. 에이전트 스택 안에서 언어와 결정이 분리되면, 디버깅과 책임 추적, 안전 제약 설계의 단위도 함께 바뀌게 됩니다.

## 2. 인프라와 플랫폼 경쟁: 파이썬 워커, MCP, 에이전트 전선

**Cloudflare**는 2년 프리뷰를 거친 **Python Workers**를 정식 지원 언어로 올리며, 에지에서 돌아가는 파이썬 실행 환경을 열었습니다. Pyodide로 파이썬을 웹어셈블리로 컴파일해 V8 기반 workerd 위에서 돌리며, 멀티프로세싱과 스레드는 막혀 있지만, `workers-py`(pywrangler)로 동일 스택을 로컬에서 시뮬레이션할 수 있게 했습니다. [출처](https://simonwillison.net/2026/Sep/21/cloudflare-python-worker)

Simon Willison은 **모델 컨텍스트 프로토콜(MCP)**에 대한 "원래 나쁜 아이디어였다"는 비판에 반박하며, 제한된 에이전트 배포에서의 실용성을 강조했습니다. MCP는 에이전트가 접근할 수 있는 외부 서비스 범위를 제어하고, API 키를 에이전트 밖에 두는 인증 흐름과 사용자 UI, 강한 감사 로그를 제공한다는 점에서, 무제한 도구 호출보다 현실적인 경계 관리 도구라는 주장입니다. [출처](https://simonwillison.net/2026/Sep/20/hn-49779718)

**OpenAI**는 두 방향에서 인프라 확장을 시도했습니다. 하나는 Higgsfield AI 사례를 통해 **GPT-6 Astra**로 소상공인 대상 영상 광고 기능을 "하루 만에" 구현했다며, 모델을 제품 개발 가속 도구로 포지셔닝한 것입니다. [출처](https://openai.com/index/higgsfield-from-prompt-to-production-with-astra) 다른 하나는 **OpenAI Academy**의 학습 경로를 개발자와 리더, 교육자, 학생까지 넓혀, 조직 내부와 생태계 전반의 실무 역량을 표준화하겠다는 움직임입니다. [출처](https://openai.com/index/expanding-openai-academy-with-new-learning-paths)

한편 **Meta의 Muse**는 초기 모바일 다운로드와 일간 활성 사용자에서 ChatGPT 초기 대비 더 빠른 상승세를 보인다는 분석이 나왔지만, **Amazon**은 Muse 에이전트의 자동 브라우징과 쇼핑을 자사 정책 위반으로 보고 amazon.com 접근을 차단했습니다. [출처](https://techcrunch.com/2026/09/21/metas-muse-is-outpacing-chatgpts-early-mobile-launch) [출처](https://www.forbes.com/sites/jonmarkman/2026/09/21/amazon-blocks-metas-new-muse-ai-agent-from-shopping-on-amazoncom)

에지 파이썬, MCP, 아카데미, 에이전트 차단 사례가 한날에 겹치며, "강력한 모델"보다 어떤 실행 환경과 권한 모델 위에서 돌아가느냐가 경쟁의 핵심 축으로 떠오르고 있습니다. 에이전트가 실제 상거래와 시스템에 닿는 순간, 플랫폼과 도메인 사업자의 규칙이 가장 강한 스로틀로 작동한다는 점도 분명해졌습니다.

## 3. 에이전트와 시뮬레이션 연구: 멀티모달 환경에서의 협력

**BirdsongChat**은 LLM 기반 의미 추론과 시뮬레이션 에이전트를 잇는 **통합 파라미터 표현(UPR)**을 제안해, 3D 움직임과 공간 음향, 환경 행동을 동기화하는 하이브리드 멀티 에이전트 프레임워크를 선보였습니다. 조류 행동 시험대로 구현한 시스템에서 교차 모달 일관성 94.4%, 감정 일관성 100%, 생성 일관성 92.6%를 기록하며, 명시적 중간 표현이 제어성과 동기화를 높인다고 주장했습니다. [출처](https://arxiv.org/abs/2609.20887)

**Proxifield**는 다중 에이전트가 서로의 "의미적 근접도"를 기준으로 통신 상대를 고르는 분산 프로토콜을 제안했습니다. 드론 수색 구조와 HiddenBench 실험에서, 가장 큰 모델과 에이전트 50개 환경에서는 중앙 Star 구조 대비 보상 우위가 5.4%에서 59.5%까지 벌어졌고, 가장 심한 영구 실패 조건에서도 Star의 38.8%보다 높은 73.6% 보상을 유지했습니다. [출처](https://arxiv.org/abs/2609.20889)

**CityLearn v3**는 재생에너지 커뮤니티의 변동 멤버십과 자산, 수요 반응 요청, 국소 에너지 공유, 데이터와 장비 실패까지 한 환경에서 시뮬레이션하는 프레임워크를 제시했습니다. 건물과 상전력 한계, 시간해상도를 엄격히 관리하고, 컨트롤러 요청과 실제 적용 행동을 분리 기록해, 서비스 제공과 정산, 집계가 짧은 피크를 어떻게 숨기는지까지 평가할 수 있게 했습니다. [출처](https://arxiv.org/abs/2609.21570)

**Bayesian Belief Layer** 논문은 LLM 에이전트의 언어 출력과는 별도의 최소 신념 레이어를 도입한 **Bayesian Chronicle Agents(BCA)**를 제안했습니다. 발화마다 한 번의 베이지안 업데이트로 확률적 입장을 갱신하고, 단일 파라미터 κ로 "고집"을 조절해 합의, 지속적 불일치, 소수 의견 영향이라는 세 가지 군집을 재현했으며, Friedkin–Johnsen 모델과 R² 0.93~0.99 수준에서 일치했습니다. [출처](https://arxiv.org/abs/2609.21997)

이들 연구는 "거대한 하나의 모델"이 아니라, 명시적 중간 표현과 분산 통신 규칙, 독립된 신념 레이어를 가진 에이전트 집합이 복잡한 물리·사회 환경을 다루는 방향으로 흐름이 이동하고 있음을 보여줍니다. 특히 견해와 협력 구조를 수학적으로 통제 가능하게 만드는 시도가, 향후 멀티 에이전트 시스템의 규제와 책임 논의의 기초가 될 수 있습니다.

## 4. 모델 효율·안전·추론: 프루닝, 토크나이저, 기권과 오디오

Hugging Face는 LLM 블록 프루닝을 **이징 모델 최적화 문제**로 재구성해, 각 블록 제거 결정을 스핀 변수로 보며 조합 최적화를 푸는 방법을 제안했습니다. 양자 영감을 받은 솔버로 어느 블록을 제거할지 고르는 접근으로, 무차별 프루닝이 아닌 구조적 압축 설계의 길을 탐색합니다. [출처](https://huggingface.co/blog/MultiverseComputingCAI/pruning-llms-like-a-physicist-block-removal-as-an)

같은 팀은 **tokenizers v1**를 주제로 인코딩, 디코딩, 스케일링 특성을 계량적으로 분석한 포스트도 냈습니다. 세부 내용은 공개 요약에 없지만, 토크나이저 레벨에서의 성능 측정과 스케일링 데이터가 모델·인프라 설계의 하한선을 규정해 간다는 메시지입니다. [출처](https://huggingface.co/blog/tokenizers-v1)

"Rewarding Efficient Reasoning" 논문은, 현재 추론 모델이 답을 모르는 질문에서 오히려 더 긴 사고 체인을 생성한다는 역행적 행동을 지적했습니다. 저자들은 과제 정보가 충분한지부터 효율적으로 판단하도록 **GRPO 보상**을 설계해 4억 파라미터급 모델을 파인튜닝했고, 평균 12.8%의 기권 행동 개선과 44%의 사고 체인 길이 감소를, 정답률 손상 없이 달성했다고 보고했습니다. [출처](https://arxiv.org/abs/2609.20846)

**SPARE**는 오디오 추론에서 최종 결론의 의미를 Sentence-BERT 임베딩으로 요약해, 이에 가까워지도록 특수 레지스터 토큰을 학습시키는 방법입니다. SALMONN 모델을 기반으로 MMAU와 MMAR 벤치마크에서 제로샷 성능이 좋아졌고, 추가 추론 비용 없이 오디오 입력에 대한 초기 주의가 향상됐다고 합니다. [출처](https://arxiv.org/abs/2609.20849)

의료 분야에서는 **HERMES**가 LLM 도움으로 임상 노트에서 개인화 지식그래프를 추출하고, 치료 실패를 포함한 시계열 대비 정보를 반영해 환자 결과를 예측하는 방법을 제안했습니다. MIMIC-III와 MIMIC-IV 데이터셋에서 텍스트 전용 강한 기준선보다 성과를 높였으며, 명시적 관계 모델링과 대비 논리가 예측력을 끌어올린다는 결론입니다. [출처](https://arxiv.org/abs/2609.20825)

**VISPATH**는 멀티모달 지식그래프 질의응답에서, 질문과 이미지로부터 "현재 홉의 의도"를 추론해 출발 엔티티와 탐색 경로를 선택하고, 일관성 검사를 통해 추론 체인을 가지치기하는 프레임워크입니다. GPT-4o를 백본으로 VISPATH-Bench와 세 개 추가 벤치마크에서 기존 강력한 기법들을 이겼고, 2홉 추론에서는 GPT-5.4 대비 13.1% 상대 정확도 우위를 보였습니다. [출처](https://arxiv.org/abs/2609.20843)

이 축의 연구는 모델을 더 작고 효율적으로 만들면서, "언제 말하지 말아야 하는지"와 "어디를 봐야 하는지"를 학습시키는 방향으로 나아가고 있습니다. 프루닝과 토크나이저, 기권 보상, 오디오·지식그래프 추론 기법은 각기 달라 보이지만, 공통적으로 LLM을 범용 생성기가 아닌, 잘 설계된 제약과 구조 안에서 움직이는 엔진으로 바꾸려는 시도입니다.

## 5. 인간 중심 회의론과 통제: 매장, 글쓰기, 플랫폼의 역풍

**OpenAI**는 "다음 단계의 AI"를 위한 글로벌 **표준과 거버넌스** 필요성을 강조하며, 개발사와 평가자, 정책 입안자가 함께 하는 평가·보고·규범 틀을 제안했습니다. 동시에 **수학과 AI 자문 그룹**을 꾸려, 수학적 성과를 어떻게 검토·공유할지에 대한 외부 자문 구조도 만들었습니다. [출처](https://openai.com/index/building-standards-next-phase-ai) [출처](https://openai.com/index/advisory-group-on-mathematics-and-ai)

TechCrunch는 이 수학 자문 그룹이 OpenAI 시스템이 해결했다는 100개 이상의 열린 문제를 둘러싼 연구를 자문하되, 연구 속도나 방향을 통제할 권한은 없다고 전했습니다. RAND 보고를 요약한 Import AI는 미국이 **"모든 옵션을 열어 두는" 초지능 전략**, 즉 특정 접근에 베팅하기보다 분산 투자와 유연성을 택해야 한다는 제안을 전했습니다. [출처](https://techcrunch.com/2026/09/21/openai-forms-math-advisory-group-as-its-ai-resolves-more-than-100-open-problems) [출처](https://jack-clark.net/2026/09/21/import-ai-473-the-uss-superintelligence-strategy-human-brain-in-a-mouse-skull-and-machine-hermeneutics)

현장에서는 다른 기류도 뚜렷합니다. 애플 스토어를 설계한 Ron Johnson은, 실리콘밸리가 그리는 AI 쇼핑 비전에 회의적이라며, 애플 성공의 핵심은 잘 훈련된 직원과 물리적 경험에 있었다고 강조했습니다.

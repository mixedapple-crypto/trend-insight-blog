## 1. ttok로 토큰 세기: GPT‑5/6 기준 정렬

**ttok 1.0**이 2026-10-09에 공개되면서 기본 토크나이저가 GPT‑4 계열에서 **GPT‑5/6 계열**로 바뀌었습니다. 하루 전 나온 **ttok 0.4**는 `--list-models` 옵션을 추가해 어떤 모델 토크나이저가 있는지 바로 볼 수 있게 했습니다. 새 OpenAI 모델 기준으로 토큰을 재는 기본 도구가 정리된 셈입니다. [출처](https://simonwillison.net/2026/Oct/9/ttok)  

### 어떻게 쓰는가: 설치, 모델 선택, 워크플로

1) **설치 및 업데이트**

```bash
# 일반 설치 또는 업그레이드
pip install --upgrade ttok

# uv를 쓰는 환경이라면
uvx ttok --help
```

2) **파일 토큰 세기**

```bash
cat prompt.txt | ttok           # 기본: GPT‑5/6 패밀리 토크나이저
ttok prompt.txt                 # 파일 경로 직접 전달
```

CLI 출력으로  
- 토큰 개수  
- 실제 토큰화된 토큰 시퀀스  
를 바로 확인할 수 있습니다.

3) **모델별 토크나이저 목록 확인**

```bash
ttok --list-models
```

강의나 사내 문서에서  
- “이 프롬프트는 `gpt-6-luna` 기준 2,100토큰입니다”  
처럼 **모델 기준을 명시**해줄 때, 여기서 목록을 확인하고 맞춰 쓰면 됩니다.

4) **특정 모델 기준으로 세기**

버전에 따라 다르지만 일반적으로는 다음 패턴을 사용합니다.

```bash
# 예시: GPT‑6 Luna 기준
cat prompt.txt | ttok --model gpt-6-luna
```

`--list-models` 결과에서 실제 모델 이름을 확인해 맞게 바꾸면 됩니다.

### 실전 팁 / 베스트 프랙티스

- **프롬프트 설계용 기준 통일**  
  팀에서 “프롬프트 길이 가이드라인”을 만들 때, 이제는 **GPT‑5/6 토크나이저**를 기준으로 숫자를 잡는 편이 좋습니다.  
  예: “사내 지침: gpt‑6‑luna 요청은 6,000토큰 이하로 작성. 측정은 `ttok --model gpt-6-luna` 결과 기준.”

- **비용 추산과 토큰 한도 체크 자동화**  
  CI 스크립트나 프롬프트 레포에서 다음처럼 토큰 수를 자동 체크하게 만들 수 있습니다.

  ```bash
  TOKENS=$(cat system_prompt.txt | ttok --model gpt-6-luna --count-only)
  if [ "$TOKENS" -gt 6000 ]; then
    echo "system_prompt.txt too long ($TOKENS tokens)"
    exit 1
  fi
  ```

- **강의용 데모**  
  수업에서 “왜 토큰이 중요한가”를 설명할 때 `cat sample.py | ttok`와  
  `cat sample.py | ttok --model gpt-4.1`를 비교해 보여주면  
  **모델별 토큰화 차이와 비용 영향**을 직관적으로 전달할 수 있습니다.

## 2. 비용·성능 튜닝: Haiku 5.5, Codex 라우팅, ChatGPT Work

**Claude Haiku 5.5**가 GPT‑6 Luna와 같은 가격대에서 더 나은 추론·코딩 성능을 목표로 공개되었습니다. [출처](https://www.latent.space/p/ainews-claude-haiku-55-better-than)  
**LegalOn**은 Codex 계열 모델을 업무 유형별로 라우팅해 **일일 Codex 비용을 약 65% 절감**했고, [출처](https://openai.com/index/legalon-halves-codex-costs)  
**Oracle**은 ChatGPT Work와 Codex를 붙여, 며칠 걸리던 전문 작업을 **수분 단위 워크플로**로 바꾸었습니다. [출처](https://openai.com/index/oracle)  

### 어떻게 쓰는가: 모델 선택과 라우팅 구조

1) **Claude Haiku 5.5 선택**

- 콘솔: 모델 선택기에서 **"Claude Haiku 5.5"** 선택  
- API 예시:

  ```python
  from anthropic import Anthropic

  client = Anthropic(api_key="...")

  resp = client.messages.create(
      model="haiku-5.5",
      max_tokens=1024,
      messages=[{"role": "user", "content": "다음 코드를 리팩터링해 주세요: ..."}],
  )
  ```

**용도 추천**  
- PR 설명 요약, 코드 리뷰 초안  
- 테스트 코드 생성, 간단한 스크립트 초안  
- 튜토리얼용 예제 코드 생성  

고비용 모델(Claude Opus, GPT‑6 Astra)은  
- 난이도 높은 알고리즘 설계,  
- 긴 맥락 리팩터링,  
- 복잡한 멀티파일 코드베이스 이해  
에 한정하는 전략이 효율적입니다.

2) **Codex 라우팅 패턴 (LegalOn 사례 일반화)**

- 업무 유형을 먼저 정의합니다.  
  예: “간단 리팩터링”, “대규모 변환”, “보안 크리티컬 분석”

- 각 유형을 **모델 매트릭스**에 매핑합니다. 예:

  | Task                         | 기본 모델         | 대체 모델            |
  |-----------------------------|-------------------|----------------------|
  | 스니펫 리팩터링, 예제 코드   | Codex Luna Small  | Haiku 5.5            |
  | 대형 코드 변환, 마이그레이션 | Codex Astra       | GPT‑6 Astra          |
  | 규정 준수·보안 점검         | Codex Sol         | Claude Opus 5.5      |

- 라우팅 코드 예시:

  ```python
  def choose_model(task_type: str):
      if task_type in {"snippet_refactor", "examples"}:
          return "codex-luna-small"
      if task_type == "large_refactor":
          return "codex-astra"
      if task_type == "compliance":
          return "codex-sol"
      return "codex-luna-small"

  def run_code_task(task_type, prompt):
      model = choose_model(task_type)
      # 공통 호출 래퍼
      return call_model(model=model, prompt=prompt)
  ```

3) **ChatGPT Work + Codex로 워크플로 만들기 (Oracle 패턴)**

- **전문가 플레이북 설계**  
  도메인 전문가에게 실제 작업 절차를  
  1단계, 2단계, 3단계 형태로 글로 받습니다.  
  예: 채용 스크리닝, 로그 기반 장애 분석, 보안 체크리스트 점검.

- 각 단계를  
  - ChatGPT Work 프롬프트 템플릿  
  - Codex 스크립트(파이썬, 셸 등)  
  로 나눠서 정의합니다.

- 플레이북 예시 구조:

  1. 입력 양식: JD, 후보자 이력서 링크  
  2. ChatGPT Work: JD 요약, 요구 역량 추출  
  3. Codex: 이력서 파싱 스크립트 생성/실행  
  4. ChatGPT Work: 역량과 이력 매칭, 평가 리포트 생성  

### 실전 팁 / 베스트 프랙티스

- **“비용 막대”로 가시화**  
  강의나 사내 문서에서 업무 유형별로  
  - “추천 모델”  
  - “예상 비용 레벨(1~5)”  
  을 막대 그래프로 표현하면  
  개발자들이 스스로 적절한 모델을 선택하는 데 도움이 됩니다.

- **벤치마크 첫 세트는 “작게, 다양하게”**  
  모델 라우팅 전 벤치마크 세트는  
  - 요청 10~20개  
  - 난이도와 길이, 언어를 섞어서  
  구성하는 편이 좋습니다.  
  많은 수보다 **다양성**이 모델 선택에 더 유효합니다.

- **강의에서 Haiku 5.5 vs GPT‑6 비교 시나리오**  
  동일 문제를 두 모델에 던져  
  - 코드 품질  
  - 오류 메시지 친절도  
  - 속도  
  를 비교해 보게 하면,  
  “같은 가격대 모델을 갈아타는 것만으로도 ROI가 달라진다”는 메시지를 전달하기 좋습니다.

## 3. 프로덕션 품질·보안: AQuA, Anthropic 정책, 격리 전략

구글은 **AQuA(Ambient Quality Agent)**라는 오픈소스 레퍼런스를 공개해, 운영 중인 에이전트의 **조용한 품질 저하**를 자동으로 잡는 방식을 제시했습니다. [출처](https://developers.googleblog.com/the-outer-loop-insights-first-an-ambient-quality-agent-that-diagnoses-your-production-agent)  
Anthropic는 **Genesis 미션**으로 과학 연구 지원을 약속하고, [출처](https://www.anthropic.com/news/genesis-mission-commitment)  
**Cyber Mission**과 **2026 Usage Policy 업데이트**로 보안·규제 리스크 대응 방식을 다듬었습니다. [출처](https://www.anthropic.com/news/anthropic-cyber-mission) [출처](https://www.anthropic.com/news/2026-usage-policy-update)  
OpenAI 내부의 **Partition Principle** 실천과 영향력 조작 네트워크 차단 사례는, 실무에서도 모델·데이터를 어떻게 격리해야 하는지를 보여줍니다. [출처](https://karagila.org/2026/openai-pp) [출처](https://openai.com/index/disrupting-ai-enabled-false-front-operations)  

### 어떻게 쓰는가: 모니터링·정책·격리 워크플로

1) **AQuA로 운영 에이전트 진단**

- 배치 방식  
  - GCP에서 프로덕션 에이전트 옆에 AQuA를 배포합니다.  
  - 에이전트 로그(대화 기록, 툴 호출 결과)를 Pub/Sub나 로그 싱크로 전달합니다.

- 동작 흐름  
  1. AQuA가 트래픽 샘플을 읽습니다.  
  2. 비정상 응답 패턴을 **클러스터링**합니다.  
  3. 기대 동작(스펙, 테스트 케이스)과 비교합니다.  
  4. 문제 케이스를 **특정 소스 스냅샷**과 연결합니다.

- 활용 포인트  
  - “지난주 배포 이후, 한국어 문의 요약만 품질이 떨어졌다” 같은  
    **부분적 회귀**를 신속히 찾는 데 적합합니다.

2) **Anthropic Usage Policy를 런타임에 녹이기**

- 정책 문서를 검토해, 사내에서 금지할 범주를  
  - 생물·보건  
  - 금융 투자 조언  
  - 자동화 해킹 도구  
  등으로 라벨링합니다.

- **프리필터 미들웨어** 예시:

  ```python
  def is_disallowed(prompt: str) -> bool:
      # 간단한 키워드 + 정규식 + 소형 분류 모델 조합
      ...

  def guarded_call(model, prompt):
      if is_disallowed(prompt):
          raise ValueError("정책상 허용되지 않는 요청입니다.")
      return call_model(model, prompt)
  ```

- CI/CD에서 “정책 테스트” 추가  
  - 금지 프롬프트 모음에 대해  
    - 모델 호출이 차단되는지  
    - 우회 표현에 대한 대응이 적절한지  
  를 자동 테스트에 포함합니다.

3) **Partition Principle 스타일 실험 격리**

- 실험마다 **프로젝트/티켓 ID**를 강제합니다.  
  예: `MAT-EXP-2026-10-09-01`

- 데이터와 체크포인트 구조:

  ```text
  s3://ml-experiments/MAT-EXP-2026-10-09-01/data/...
  s3://ml-experiments/MAT-EXP-2026-10-09-01/checkpoints/...
  ```

- 모델 배포 경로를 분리합니다.  
  - `/qa/exp/...` 엔드포인트  
  - `/prod/...` 엔드포인트  
  를 네이밍부터 구분하고,  
  프로덕션 키에서는 **실험 엔드포인트 접근 금지**를 기본값으로 둡니다.

4) **영향력 조작·허위 프론트 탐지 포인트**

- 자체 서비스에 AI 기능을 붙였다면,  
  **계정 패턴 모니터링**을 추천합니다.

  - 같은 IP 범대역 또는 호스팅에서 다수 계정 생성  
  - 유사한 이력서·프로필 이미지  
  - 동일한 포맷의 “전문가 의견” 반복 게시  

- 모델을 사용할 때는  
  - 정치·사회 이슈에 대한 자동 대량 생성  
  - “가상 전문가”를 꾸며 대변하는 프롬프트  
  를 자체 정책에서 명시적으로 막는 편이 안전합니다.

### 실전 팁 / 베스트 프랙티스

- **A/B 실험에 AQuA 연결**  
  새 에이전트 버전을 배포할 때  
  - A/B 그룹 모두 AQuA에 연결하고  
  - 실패 클러스터를 비교  
  하면, “전체 승률은 비슷하지만 특정 도메인에서만 나빠졌다”는 신호를 빨리 잡을 수 있습니다.

- **수학·형식화 리포지토리 작업 시 변경 로그 체크**  
  OpenAI 수학 형식화 저장소처럼,  
  철회·수정 이력이 잦은 레포에서 강의 자료나 자동 증명 파이프라인을 만들 때는  
  - 의존하는 레마·정리의 커밋 ID를 명시  
  - 수업 전날 `git log`로 철회 여부 확인  
  하는 플로우를 두면 재작업을 크게 줄일 수 있습니다.

- **“AI가 다 한다” vs “문제 정의가 다 한다”**  
  Carson Gross가 말하는 것처럼,  
  핵심은 여전히 **문제 분해와 복잡도 관리**입니다. [출처](https://simonwillison.net/2026/Oct/8/carson-gross)  
  실무와 강의에서  
  - “문제 정의 → AI 도구 설계 → 모니터링/정책”  
  세 단계를 항상 분리해서 보여주면,  
  수강생이 도구 의존 대신 **엔지니어링 감각**을 배우는 데 도움이 됩니다.

## 4. 멀티모달·지능형 UI: Opus 5.5, Pollo, ChatGPT UI와 교육 활용

**Claude Opus 5.5**는 한 번의 긴 세션으로 **three.js 인터랙티브 비주얼라이제이션**을 끝까지 만든 사례가 나오고, [출처](https://news.hada.io/topic?id=35013)  
뮤직비디오 데모로 **오디오+비디오 생성 능력**도 과시했습니다. [출처](https://www.youtube.com/watch?v=3TNpOD6bov8)  
**Pollo AI**는 GPT‑5.6, GPT‑6 Astra, GPT‑Image‑2.5를 얹어 캠페인 브리프를 영상 광고까지 연결하고, [출처](https://openai.com/index/pollo-ai)  
ChatGPT는 **Intelligent UI**와 **Advanced Data Analysis(코드 인터프리터) 파일 업로드 표시 개선**으로 인터랙티브 작업 흐름을 다듬었습니다. [출처](https://tldr.tech/ai/2026-10-08) [출처](https://www.latent.space/p/ainews-not-much-happened-today-60f)  

### 어떻게 쓰는가: 프로젝트·수업에 녹이는 워크플로

1) **Opus 5.5로 “한 프롬프트 장기 세션” 운영**

- 초기 프롬프트에서 반드시 고정합니다.  
  - 기술 스택: 예) three.js, pnpm, Vite  
  - 런타임 제약: 브라우저만 사용, 서버리스 없음  
  - 목표 상태: “데이터셋 X를 3D 상호작용 뷰로 시각화”

- 예시 프롬프트 구조:

  > - Italo Calvino “보이지 않는 도시들” 모든 도시를 데이터로 본다.  
  > - three.js와 pnpm으로 SPA를 만든다.  
  > - 마우스 인터랙션, 도시별 툴팁, 필터 UI를 포함한다.  
  > - 6시간 세션 동안 스스로 테스트하고 에러를 고친다.  
  > - 각 단계에서 변경된 파일 전체를 다시 보여준다.

- 세션 운영 팁  
  - 중간에 “새 질문” 대신  
    “위 사항을 유지한 채, 다음 버그를 수정해라”처럼  
    **컨텍스트를 끊지 않는 요청**을 합니다.  
  - 코드 실행은 로컬에서 하고, 에러 메시지를 그대로 피드백합니다.

2) **Opus 5.5 음악·영상 생성 시 프롬프트 패턴**

뮤직비디오 데모 구조를 그대로 따라 하면 좋습니다.

- 1단계: 곡 정보  
  - BPM, 장르, 길이(예: 120BPM, 3분, 로파이)  
- 2단계: 씬 타임라인  
  - 0–20초: 도시 전경, 드론 샷  
  - 20–40초: 인물 클로즈업, 저녁 조명  
- 3단계: 시각 스타일  
  - “낮은 채도, 그레인 필름, 35mm 감성”

프롬프트 예:

> - 3분 길이 로파이 힙합 곡에 맞는 뮤직비디오를 만든다.  
> - 10초 단위로 씬을 나누고, 각 씬마다 배경, 인물, 카메라 움직임과 색감을 정의한다.  
> - 템포는 일정하게 유지하고, 장면 전환은 킥 드럼에 맞춘다.

3) **Pollo AI로 캠페인 샘플 제작**

- 입력 템플릿 설계  
  - 제품 설명  
  - 타깃 오디언스  
  - 캠페인 목표(KPI)  
  - 브랜드 톤(예: 공식적, 유머러스, 실험적)  
  - 채널(유튜브, 인스타, 틱톡)

- 워크플로 예  
  1. 텍스트 브리프로 Pollo에 입력  
  2. **스토리보드 이미지** 초안 생성  
  3. 수정 사항 반영 후 **시네마틱 영상 렌더**  
  4. 내부 피드백 후 최종본 수출

강의나 클라이언트 워크숍에서  
- “브리프만 바꾸고, 도구 셋은 그대로”  
를 반복해 보여주면,  
브랜드 전략과 AI 제작의 연결 지점을 설명하기 좋습니다.

4) **ChatGPT Intelligent UI + Advanced Data Analysis 활용**

- Intelligent UI 켜기  
  - Settings → Labs → **Intelligent UI** 활성화  
  - 또는 화면 상의 안내 배너에서 바로 허용

- 개발·강의 활용 포인트  
  - 입력 중 제안되는 **프롬프트 템플릿**을 바로 쓰지 말고,  
    “이 템플릿의 스코프를 줄이는” 방향으로 수정해  
    과제나 데모를 더 집중되게 만듭니다.  
  - 코드나 SQL 결과의 **인라인 미리보기**를 사용해  
    실행 전 결과를 검산하는 습관을 보여주면,  
    “모델 결과도 검증 대상”이라는 메시지를 줄 수 있습니다.

- Advanced Data Analysis 파일 업로드 개선  
  - 세션 사이드바에 **남은 업로드 용량**이 바로 표시됩니다.  
  - 여러 CSV, 파켓 파일을 올리는 수업이라면  
    업로드 전에 용량을 확인하고  
    “훈련용 10개, 과제용 2개”처럼 미리 계획을 세울 수 있습니다.

### 실전 팁 / 베스트 프랙티스

- **“한 세션, 한 목표” 원칙**  
  Opus 5.5처럼 긴 세션이 가능할수록,  
  “도중에 문제를 자꾸 바꾸는 습관”이 생산성을 떨어뜨립니다.  
  수업과 실무 모두에서  
  - 세션 시작 시 목표와 제약을 명문화  
  - 목표 달성 시 세션을 닫고, 새 목표는 새 세션에서 시작  
  하는 방식이 결과물 일관성을 높입니다.

- **SaaS 피벗 전략과 연결**  
  AI 시대 SaaS 피벗 논의에서  
  - “코드와 기능”보다  
  - **운영 인프라와 직소유 채널**이 모at이라는 관점이 나왔습니다. [출처](https://news.hada.io/topic?id=35041)  
  오늘 소개된 AQuA, Cyber Mission, Usage Policy, Intelligent UI 같은 흐름을 보면  
  **관측·운영·정책·UX 레이어에 투자한 팀**이 결국 차별화를 가지게 되는 구조와 맞닿습니다.

- **숫자와 과장 구분하기**  
  OpenAI의 연환산 매출이 680억이 아니라 **500억 달러 수준**이라는 정정은, [출처](https://news.hada.io/topic?id=35028)  
  공급사 발표를 교육·전략 자료에 인용할 때  
  - 무엇이 “파트너 포함 총액”인지  
  - 무엇이 “순매출, 같은 기준”인지  
  를 까다롭게 따져야 한다는 신호입니다.  
  모델 선택과 더불어 “숫자를 읽는 법”까지 같이 가르칠 때,  
  개발자와 강사는 AI 도구를 **과장이 아닌 실속**으로 다루는 팀을 만드는 데 더 가까워집니다.

## 1. Mistral 오픈 가중치 2종: 로컬 코드·멀티모달 세팅

**무엇이 새로웠나**

- **AIE Code 컨퍼런스**에서 Mistral이 **코딩 특화 오픈 가중치 모델**을 공개했습니다.  
- 동시에 **Mistral Large 4 OSS**가 나와, 이전보다 나은 지시 이해와 멀티모달을 지원합니다.  

둘 다 로컬에서 직접 다운받아 추론과 파인튜닝이 가능합니다.

### 1-1. 설치와 기본 사용 흐름

1) 저장소 클론과 의존성 설치  
- 공식 Mistral GitHub 또는 모델 허브에서 저장소를 클론합니다.  
- `transformers`, `accelerate`, `onnxruntime` 또는 선호 런타임을 설치합니다.
  ```bash
  pip install "transformers>=4.44" accelerate onnxruntime
  ```

2) 가중치 다운로드  
- 모델 카드에서 체크포인트 이름을 확인합니다. 예시:
  ```bash
  git lfs install
  git clone <mistral-code-model-repo>
  git clone <mistral-large-4-oss-repo>
  ```

3) 포맷 변환(PyTorch → ONNX/FP16/양자화)  
- 저장소에 제공된 변환 스크립트를 실행합니다.
  ```bash
  python convert.py \
    --model ./mistral-code \
    --to onnx \
    --dtype fp16 \
    --output ./mistral-code-fp16-onnx
  ```

- 개발용과 엣지 배포에는 **FP16 또는 4/8비트 양자화 ONNX**를 우선 추천합니다.  
  메모리와 레이턴시를 크게 줄이면서 정밀도 손실은 제한적입니다.

4) 로컬 추론(Transformers 예시)
```python
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "mistral-code-model"  # 또는 "mistral-large-4-oss"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(
    name,
    torch_dtype="auto",
    device_map="auto",
)

prompt = "You are a senior Python engineer.\n\nTask: write a function that deduplicates a list while preserving order.\n\nCode:"
x = tok(prompt, return_tensors="pt").to(model.device)
out = model.generate(**x, max_new_tokens=200)
print(tok.decode(out[0], skip_special_tokens=True))
```

### 1-2. 파인튜닝과 실전 팁

1) Hugging Face Trainer로 코드 특화 파인튜닝  
- 깃허브 이슈, 사내 코드 리뷰 코멘트, 스타일 가이드를 섞어 **지시+코드** 데이터셋을 만듭니다.  
- `Trainer` 또는 LoRA 어댑터로 소규모 데이터(수만~수십만 샘플) 파인튜닝을 진행합니다.

```python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
)

model = get_peft_model(model, config)
# Trainer(...)로 학습
```

2) 멀티모달 개발자 워크플로  
- **Mistral Large 4 OSS**는 이미지+텍스트를 다루므로 다음 작업에 바로 투입 가능합니다.
  - 에러 스크린샷에서 로그 추출 후 디버깅 설명.  
  - 화이트보드 사진에서 UML 추출 후 코드 골격 생성.  
  - 수식 캡처에서 테스트 코드 생성.

- vLLM이나 Ollama 사용 시:
  - vLLM: 배치 추론과 서버 모드로 팀 공용 엔드포인트 구성.  
  - Ollama: 개발자 PC 로컬에 올리고 IDE 플러그인과 연결.

3) 강의·사내 교육 활용 팁  
- 강의나 사내 워크숍에서 **“클라우드+로컬 비교 실습”**을 설계하면 좋습니다.
  - 같은 과제를 OpenAI/Mistral API와 Large 4 OSS에 동시에 던집니다.  
  - 응답 품질, 레이턴시, 비용, 프라이버시를 비교해 **모델 선택 판단 기준**을 체험하게 할 수 있습니다.

## 2. NESformer: LLM을 6502 가상머신으로 쓰는 법

**dbreunig/nesformer**는 **Qwen3.5-4B 가중치 안에 NES 6502 CPU 에뮬레이터를 “구워넣은” 프로젝트**입니다. 슈퍼 마리오 같은 NES ROM이 모델 내부에서 실행됩니다. 속도는 느리지만, “LLM을 가상머신처럼 쓰는” 실험에 좋은 참고 사례입니다. [출처](https://simonwillison.net/2026/Oct/30/nesformer)

### 2-1. 설치와 ROM 실행

1) 저장소 가져오기
```bash
git clone https://github.com/dbreunig/nesformer.git
cd nesformer
pip install -r requirements.txt
```

2) 제공된 Qwen3.5-4B 번들 로드  
- README에 안내된 위치에서 모델 가중치를 다운로드합니다.  
- 로컬 GPU 또는 충분한 RAM이 있는 CPU 환경을 준비합니다.

3) CLI로 NES ROM 실행
```bash
python nesformer_cli.py \
  --model ./qwen3.5-4b-nesformer \
  --rom ./roms/super_mario_bros.nes
```

- 프레임레이트는 네이티브 에뮬레이터보다 매우 느립니다.  
- 인터랙션보다는 **동작 검증과 데모** 목적이 적합합니다.

### 2-2. 6502 테스트와 프롬프트 분석 활용

1) 6502 적합성(conformance) 테스트 실행  
- 저장소에 포함된 6502 테스트 ROM을 대상으로 CLI를 돌려,  
  모델이 CPU 상태를 얼마나 정확히 재현하는지 확인할 수 있습니다.  

- 이 때 나오는 **상태 추적 로그**는 “LLM에 내장된 로직이 얼마나 결정론적인가”를 보는 좋은 자료입니다.

2) Opus 5.5 프롬프트 벤치마크  
- 프로젝트에 포함된 **Opus 5.5용 프롬프트와 래퍼**를 분석하면,  
  “모델에게 상태를 순차적으로 넘기며 실행기를 흉내 내는 패턴”을 그대로 재활용할 수 있습니다.
- 예:
  - 커스텀 DSL 인터프리터를 LLM 안에 심기.  
  - 교육용 CPU/VM 시뮬레이터를 코드 없이 프롬프트로만 구현.  
  - 모델 버전마다 동일한 DSL 동작을 재현하는지 회귀 테스트.

### 2-3. 실전 팁: 모델-as-VM 워크숍 설계

- 개발자 교육이나 대학 강의에서 다음 구성에 활용할 수 있습니다.
  1. 첫 세션: NESformer 구조 해부(프롬프트, 상태 인코딩, 토큰 포맷).  
  2. 둘째 세션: 참가자마다 “나만의 VM 또는 DSL 인터프리터”를 LLM으로 구현.  
  3. 마지막: 모델 크기, 토크나이저, 상태 표현 방식에 따른 **속도·정확도 트레이드오프** 비교.

- 이렇게 하면 **“모델을 함수”가 아니라 “모델을 VM”으로 보는 관점을** 실습으로 체득시킬 수 있습니다.

## 3. Vicem과 Shellside: 에이전트 전환과 캔버스 워크플로

오늘 나온 **Vicem**과 **Shellside**는 각기 다른 방식으로 개발자 에이전트 워크플로를 확장합니다. 하나는 로컬 에이전트 사이의 컨텍스트 이송, 다른 하나는 “생성형 캔버스+Claude Code”입니다.

### 3-1. Vicem: 에이전트 간 컨텍스트 전송 도구

**Vicem**은 로컬 AI 코딩 에이전트 간에 **작업 컨텍스트를 넘겨주는 CLI/GUI**입니다. [출처](https://news.hada.io/topic?id=36286)

1) 기본 사용 흐름  
- Vicem 실행 후, 현재 사용하는 에이전트에서:
  - 작업 디렉터리, 열려 있는 파일, 최근 프롬프트/응답 이력을 캡처합니다.  
  - 이를 “스냅샷”으로 저장하고 다른 에이전트로 전송합니다.
- 대상 에이전트에서 Vicem가 제공한 스냅샷을 불러오면:
  - 동일한 파일 셋과 문맥이 준비되어 **질문을 이어서** 할 수 있습니다.

2) 실전 팁  
- 자주 쓰는 에이전트(예: Cursor, Gemini CLI, 로컬 Claude Code)에 대해  
  Vicem 호출 스크립트를 만들고 **단축키로 묶는 것**이 좋습니다.
  - 예: `Ctrl+Alt+V` → “현재 컨텍스트를 Vicem로 푸시 후, 다른 IDE에서 풀기”.
- 강의 현장에서는:
  - “버그 분석은 Claude Code, 리팩터링과 문서화는 다른 모델”처럼 역할을 나누고,  
  - Vicem으로 컨텍스트만 넘기는 **멀티 에이전트 협업 패턴**을 보여줄 수 있습니다.

### 3-2. Shellside: Claude Code 상주 생성형 캔버스

**Shellside**는 웹 기반 보드마다 하나의 **Claude Code 인스턴스와 터미널**이 붙어 있는 “생성형 캔버스”입니다. [출처](https://news.hada.io/topic?id=36285)

1) 기본 사용법  
- 새 보드를 만든 뒤, 보드 하단 터미널에 자연어로 요청합니다.
  - 예:  
    - “열 A/B/C를 가진 칸반 보드와 CSV 임포트 뷰를 만들어 달라.”  
    - “이 보드에 코드 리뷰 체크리스트 위젯을 추가해 달라.”
- Claude Code가 UI와 도구를 생성해 보드 위에 바로 배치합니다.  
  필요하면 다시 터미널에 “열 이름 바꿔 달라”, “필터 기능 추가해 달라” 등으로 반복 요청합니다.

2) 실전 팁  
- 개발자·강사 워크플로:
  - 프로토타입 도구를 “코드 없이 대화로” 만들어,  
    수업용 보드, 데모용 툴, 간단한 팀 보조 도구를 빠르게 반복 제작할 수 있습니다.
  - 강의 때 학생들에게 “자기만의 디버깅 대시보드”를 직접 설계하게 하면,  
    UI 설계 사고와 도구 활용 능력을 같이 키울 수 있습니다.

- 보안 관점:
  - 보드에 올리는 코드나 데이터에 민감 정보가 없는지 점검해야 합니다.  
  - 팀 공용 보드에서는 권한과 공유 범위를 최소 권한 원칙으로 설정하는 것이 좋습니다.

## 4. Cursor Claude Code 백도어: IDE 보안 체크리스트

Cursor 마켓플레이스의 **Claude Code 확장**이 변조되어 **SSH 백도어를 배포한 사건**이 확인되었습니다. 버전 **2.1.312, 2.1.313**이 문제였고, 확장 자동 업데이트를 통해 전파되었습니다. [출처](https://news.hada.io/topic?id=36287)  
관련 분석에 따르면, 공격자는 시스템 정보 수집, SSH 키 설치, 역방향 터널과 지속성 스크립트를 심었습니다. [출처](https://news.hada.io/topic?id=36288)

### 4-1. 즉시 해야 할 조치

1) 확장 제거와 자동 업데이트 점검  
- Cursor 확장 관리자에서 문제의 Claude Code 확장을 바로 제거합니다.  
- Cursor와 사용하는 모든 IDE에서 **자동 확장 업데이트를 비활성화**합니다.

2) SSH 키와 지속성 확인  
- `~/.ssh/authorized_keys`에서 모르는 공개키를 제거합니다.  
- `/etc/rc*`, `crontab`, 로그인 스크립트에  
  낯선 스크립트나 원격 호스트로의 SSH/HTTP 호출이 있는지 점검합니다.
- 모든 SSH 키와 로그인 자격 증명을 교체합니다.

3) 네트워크 점검  
- 개발 머신에서 **비정상적인 외부 IP 연결**이 없는지 모니터링합니다.  
- CI 서버와 빌드 머신도 같은 방식으로 점검합니다.

### 4-2. 앞으로의 IDE·에이전트 보안 베스트 프랙티스

1) 확장을 “패키지”로 취급하기  
- 새로운 확장 또는 업데이트가 있을 때:
  - 공식 출처 여부, 최근 변경 로그, 코드 서명 여부를 확인합니다.  
  - 팀 내에서 “업데이트 승인 플로우”를 둡니다.
- 가능하면 **샌드박스 환경**에서 먼저 설치 후:
  - 파일 시스템 변경, 네트워크 호출을 관찰한 뒤 본 환경에 반영합니다.

2) 자동 업데이트 전략  
- 자동 업데이트는 기본적으로 꺼두고,
  - 보안 패치와 같이 꼭 필요한 경우에만 수동 업데이트를 권장합니다.
- 교육 현장과 기업에서는:
  - “매달 1회 확장 업데이트 점검일”을 정하고,  
  - 그때만 검증 후 일괄 업데이트하는 식이 안정적입니다.

3) 에이전트와 SSH 자격 증명 관리  
- 에이전트가 SSH 키 생성, 서버 접속을 제안하면:
  - 별도 “도구용 전용 계정”과 제한된 권한의 키를 사용합니다.  
  - 프로덕션 자격 증명은 에이전트가 직접 만지지 못하게 정책을 세웁니다.

- 이번 사건을 계기로,
  - “AI 에이전트 도입 가이드”에 **IDE·확장 보안 체크리스트**를 정식으로 포함할 필요가 있습니다.

## 5. OpenAI 정책·Anthropic 신용등급: 벤더 리스크와 ROI 설계

마지막으로는 **정책·재무·ROI** 신호를 묶어서 보는 것이 실무 설계에 도움이 됩니다.

### 5-1. 데이터·안전 정책: robots.txt와 청소년 보호

1) AI 학습 로봇 배제 표준  
- OpenAI가 여러 제공자와 함께, **robots.txt로 AI 학습 허용/거부를 표현**하는 방식을 따르겠다고 밝혔습니다. [출처](https://openai.com/index/helping-websites-express-ai-training-preferences)
- 사용법:
  - 웹사이트 루트의 `robots.txt`에 학습 허용 또는 거부 지시를 추가합니다.
  - 사이트 전체에 일관된 방침을 선언하면,  
    개별 요청마다 예외를 처리하는 부담이 줄어듭니다.

- 강사·데이터 엔지니어 팁:
  - 강의용 실습 서버나 사내 문서 포털에  
    “학습 허용/불허” 방침을 명시해 두면,  
    나중에 데이터 활용 범위를 설명할 때 기준이 명확해집니다.

2) ChatGPT 청소년 보호 업데이트  
- OpenAI가 **폭력 예방 강화**와 **조기 개입 로직**을 ChatGPT에 적용했습니다. [출처](https://openai.com/index/community-safety-report-and-new-protections-for-teens)
- 따로 설정할 것은 없고,  
  대화 내용에 따라 더 일찍 안내 또는 거절이 나올 수 있습니다.

- 개발자·교육자 팁:
  - 예전에 “경계선” 수준이던 폭력 관련 예시 프롬프트를 다시 테스트해 보십시오.  
  - API를 쓰는 서비스라면, 새 필터 기준을 반영해  
    자체 콘텐츠 정책과 가이드 문구를 조정하는 것이 좋습니다.

3) “공정 이용(fair use)” 입장 정리  
- OpenAI가 법원 제출 서면 일부를 소개하며  
  “공정 이용이 AI 학습 혁신을 뒷받침한다”는 논리를 정리했습니다. [출처](https://openai.com/index/fair-use-benefits-everyone)
- 데이터 정책 설계 시:
  - 이 입장을 그대로 복사하기보다,  
  - **데이터 출처 기록, 내부 리스크 리뷰**와 함께 문서화하면  
    나중에 법무 검토 시 방어 논리를 정리하기가 수월합니다.

### 5-2. 벤더 재무 리스크와 ROI 설계

1) Anthropic의 예상 ‘정크’ 신용등급  
- IPO 이후 **높은 ‘정크’ 등급**이 예상된다는 보도가 나왔습니다. [출처](https://techcrunch.com/2026/10/30/anthropic-expected-to-receive-high-junk-rating-from-credit-agencies-following-ipo-report-says)
- 이는 차입 비용과 향후 자금 조달 여력을 압박할 수 있습니다.

- 실무 팁:
  - 특정 벤더에 깊이 엮인 아키텍처라면,  
    **단기 계약, 종료 조항, 대체 벤더 경로**를 계약서에 명시하십시오.
  - 중요한 SLA가 필요한 경우,  
    재무 상태가 안정적인 벤더와 이중화를 검토하는 편이 안전합니다.

2) Credit Saison의 ChatGPT Enterprise ROI 954%  
- 일본 Credit Saison이 ChatGPT Enterprise 파일럿에서  
  **954% ROI**를 달성했다고 공개했습니다. [출처](https://openai.com/index/credit-saison)
- 성공 패턴:
  - 경영진 후원과 **현장 자발적 사용 사례**를 함께 키웠습니다.  
  - 파일럿 단계부터 KPI와 사용 예시를 정량·정성 모두 수집했습니다.

- 도입 설계 팁:
  - “엔터프라이즈 도입=고정 비용”이 아니라  
    파일럿 단계에서 ROI를 수치로 만들고,  
    그 수치에 기반해 사내 확산 예산을 설계하는 것이 설득력이 있습니다.
  - 교육에서는,
    - “챔피언 사용자”를 육성해 대표 프롬프트와 워크플로를 문서화하고,  
    - 이를 사내 템플릿으로 배포하면 확산 시 품질 저하를 줄일 수 있습니다.
